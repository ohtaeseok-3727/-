# 통합 미리보기와 게임 적용 준비

`combat-preview.html`에서 기사·마법사의 이동과 각 3개 공격을 선택한다. 이펙트, 좌우 반전, 재생 속도, 확대, 프레임 이동과 시간 탐색을 제공한다.

## 공통 데이터

`export-combat-visuals.py`가 `combat-visuals.json`, 브라우저용 `combat-visuals.js`, C++용 `SimpleGame/CombatVisualData.h`, 배포용 `PreparedCombatAssets.targets`를 함께 생성한다. PNG는 수정하지 않는다. 그림을 다시 생성하지 않아도 프레임 사각형·발 기준 좌표·배율·시간·이펙트 위치를 공유한다. 좌표는 발 기준, +x 오른쪽/+y 아래, 시간은 ms이다.

- 클래스 번호: 마법사 0, 기사 1 (기존 게임과 동일).
- 클립 ID: `mage-walk`, `knight-walk`, `mage-1`~`mage-3`, `knight-1`~`knight-3`.
- 기사 가로베기 위치 및 내려베기 효과 바닥/발 정렬은 기존 기사 미리보기 값을 유지한다.
- 마법사 1번의 원본 5프레임 제외, 효과 2배 확대가 반영된 기존 배율, 1번 전방20/위5 보정, 2번 효과0.8배, 3번 효과1.2배를 유지한다.
- 이펙트는 본체와 독립적으로 재생한다. RGB 검정 배경 효과는 가산 합성, RGBA 시트는 일반 알파 합성이다.

## 준비한 C++ 연결부

`Renderer::CombatVisual(clipId, milliseconds, footX, footY, faceLeft, scale, effects)`가 공통 데이터를 샘플링해 캐릭터와 효과를 그린다. 시트는 `LoadRawSpriteSheet`로 원본 크기와 색을 보존해 읽는다. 사용자 요청으로 `Character`는 미니 이동 클립을 사용하도록 전환했다. 두 이동 텍스처만 시작 시 로드하며 공격은 아직 게임에서 호출하지 않는다.

이동은 실제 이동 거리 80월드 단위당 8프레임 한 주기로 재생하고, 정지 시 첫 프레임을 사용한다. 상하 이동은 마지막 좌우 방향을 유지한다(현재 옆모습 시트를 연결하기 위한 구현 가정). 월드 배율은 기존 약50px 높이에 맞춰 마법사 .35, 기사 .32를 공통 데이터 배율에 추가 적용했다. 직업 선택 화면은 그 두 배이다. 실기 렌더 결과에서 크기와 발 정렬은 사용자 확인이 필요하다.

예: `renderer.CombatVisual("mage-2", attackElapsedSeconds * 1000.f, screenX, screenY, faceLeft, visualScale);`

`Sample`은 클립 완료 시 0개, `CombatVisual`은 false를 반환한다. 완료 이후에는 호출부가 대기/이동으로 전환해야 한다. 이동은 duration으로 시간을 나눈 나머지를 사용한다. 게임 크기는 기존 월드 캐릭터 높이와 비교해 visualScale을 정해야 하며, 미리보기 배율 자체가 게임 크기 확정값은 아니다.

사용자가 다음에 적용을 요청하면:

1. `PrototypeWorld`에 현재 공격·경과시간·바라보는 방향 상태를 연결한다.
2. `SimpleGame.cpp::KeyDown` 또는 마우스 입력에서 공격을 시작한다. 기존 코드는 아직 공격 입력을 갖고 있지 않다.
3. 공격 중에는 플레이어 `Character` 대신 해당 공격 클립의 `CombatVisual`을 호출한다. 기본 대기/이동은 이미 미니 이동 클립에 연결되어 있다.
4. 공격 종료/직업 선택/리셋/일시정지의 상태 처리를 연결한다. 실패 시 기존 렌더링으로 복귀할 수 있다.

공격키, 연계 입력, 공격 중 이동, 실제 타격 판정/피해량은 확정되지 않았다. 시각 효과의 좌표를 게임 판정으로 간주하지 않는다. 앞뒤 이동 시트 추가 여부도 미정이다. 좌우 반전은 장비 위치도 뒤집는다. 전 방향 공격이 필요하면 방향별 클립을 추가할 수 있다.

## 배포와 검증 범위

프로젝트에 `PreparedCombatAssets.targets`를 연결했다. 이후 사용자가 빌드하면 선택된 PNG 10개만 상대 경로를 보존해 실행 파일 옆으로 복사한다. 폐기 시트는 포함하지 않는다.

데이터 내 파일 존재·PNG 크기·프레임 경계 및 문서/코드 정적 검토만 수행했다. C++ 컴파일, 브라우저 애니메이션 실행, 게임 렌더링과 HDR/Bloom 결과는 검증하지 않았다. 브라우저와 게임의 후처리 색상 차이도 실제 실행 확인이 필요하다.
