# 로컬 월드 모니터

게임의 NPC 상태, 마을권·지역 상태, NPC와 몬스터 수를 HTML에서 확인한다. 게임이 보내는 JSON 전체 스냅샷을 로컬 서버가 수신한다. 외부 패키지 설치는 필요 없다.

## 사용 방법

1. 모니터링 코드가 포함된 게임을 Visual Studio에서 빌드한다. 기존 실행 파일에는 새 송신 기능이 없다.
2. Windows용 Python 3.10 이상과 `py` 실행기가 설치된 PC에서 [start-monitor.cmd](start-monitor.cmd)를 실행한다. 서버 창과 기본 브라우저가 열린다.
3. 같은 PC에서 게임을 실행한다. 주소는 `http://127.0.0.1:8766/`이다. HTML 파일을 직접 열면 JSON을 수신할 수 없다.
4. 지역 카드를 선택하거나 이름·상태를 검색한다. 부재 NPC와 사망 몬스터는 별도로 구분한다.
5. 종료할 때 서버 창에서 `Ctrl+C`를 누른다.

서버를 먼저 열거나 게임을 먼저 열어도 다음 전송에서 연결한다. 8766 포트를 사용 중이면 기존 모니터 서버를 확인한다. 동시에 하나의 게임 세션만 표시하며, 게임을 재시작하면 이전 세션의 마지막 수신 후 5초가 지나야 새 세션을 받는다.

게임은 약 1초 간격으로 전송하고 브라우저도 약 1초 간격으로 조회한다. 5초 이상 새 데이터가 없으면 마지막 수치를 남기면서 연결 중단을 표시한다. 테스트용 가상 데이터는 기본 화면에 넣지 않았다.

## 집계 범위

- **NPC 수**: 현재 존재하는 구현된 NPC 액터 수다. 대사 속 주민 인구나 미구현 피난민 수는 포함하지 않는다. 구출 후 퇴장한 NPC는 목록에 남아도 현재 개수에서 제외한다.
- **몬스터 수**: 모든 등록 지역의 체력 0 초과 개체다. 사망 보관 개체는 별도 표시하며 누적 처치 수가 아니다.
- **마을권**: 마을이 들어 있는 맵 전체다. 국경 마을은 농경지, 회색벽은 주변 방어선을 포함한다. 카드의 사건 해결 상태와 실제 남은 몬스터 수는 각각 표시한다.
- **비활성 지역**: 게임이 보관하는 마지막 상태다. 모니터가 해당 지역의 AI를 추가 실행하지 않는다.
- 현재 NPC 체력 시스템이 없는 대상은 `null`을 전송하고 화면에는 ‘미정의’를 표시한다. 챕터별 용사는 서로 다른 런타임 액터로 집계한다.

## 파일 역할과 프로토콜

[구현·JSON 명세](../../docs/implementation/LOCAL_WORLD_MONITOR.md)에 C++ 연결, 상태 출처, 전체 메시지 형식과 제한을 기록했다.

| 파일 | 역할 |
| --- | --- |
| [server.py](server.py) | 로컬 HTTP 수신과 HTML 제공 |
| [protocol.py](protocol.py) | 메시지 검증, 순서 확인, 최신 상태 보관과 개수 집계 |
| [web/index.html](web/index.html) | 화면 구조 |
| [web/dashboard.css](web/dashboard.css) | 화면 스타일과 좁은 화면 대응 |
| [web/dashboard.js](web/dashboard.js) | 조회, 필터, 상태·개수 표시 |
| [test_protocol.py](test_protocol.py) | 집계·순서·잘못된 메시지에 대한 수동 실행용 회귀 검사 |

## 검증 상태

이번 변경은 정적 검토만 수행했다. 게임 빌드, 서버·브라우저 실행, 회귀 검사 실행 및 실제 통신 확인은 수행하지 않았다.

사용자가 검증할 때 프로젝트 루트에서 다음 명령으로 프로토콜 회귀 검사를 실행할 수 있다.

```powershell
py -m unittest discover -s tools/monitor -p 'test_*.py'
```

게임과 서버를 실행한 뒤에는 직업 선택 → 월드 진입 → 지역 이동 → 몬스터 처치 → 포로 구출 → 메뉴 열기 → 게임 종료 순서로 표시와 5초 연결 중단 표시를 확인한다.
