# 목표 안내와 전투 판독성 개선

2026-10-08 · 브랜치 `codex/combat-guidance-polish`

## 요청과 검증 방식

사용자는 목표·상호작용 안내와 공격 판독성을 개선하고 실제 플레이 결과로 밀도·난이도를 검토하도록 요청했다. 빌드·실행·디버깅도 명시적으로 요청했다. 사용자가 PC를 사용 중이어서 이후 검증은 키보드·마우스·포커스를 사용하지 않는 숨겨진 WGL 창의 자동 플레이로 진행했다. [기존 오픈월드 흐름](OPEN_WORLD_FLOW.md)과 확정 스토리는 유지한다.

## 적용 내용

- 일반 고블린·오크의 공격 준비에 판정 반경, 준비 진행 막대, 공격/사격 문구를 표시한다. 일반 근접 55, 원거리 240의 기존 공격 거리와 0.7/1.2초 준비 시간을 판정과 표시가 함께 참조한다. 지면의 세로 투영 배율은 `SceneCamera::GroundDepthScale()`을 사용한다. 사망·치료·스크립트 병력에 일반 공격 표시를 추가하지 않는다.
- 바르칸 휘두르기·내려찍기·함성과 폭발에는 외곽선과 준비 진행 표시를 제공한다. 기존 85/110/185/95 반경을 유지하며 세로 표시를 실제 지면 투영에 맞춘다. 휘두르기는 실제로 정면 조건도 검사하므로 전체 원은 위험 반경의 보수적인 안내다. 원 내부의 벽·차폐를 시각적으로 잘라내지는 않는다.
- 농가 목표 표식은 증거 지점에서 110 단위 아래인 실제 습격 중심을 가리키며 Ctrl 공격을 안내한다. 지휘 종은 Ctrl 공격, 증원 문·협곡 장치는 Space 유지, 수용소 후속 단계는 대피 지점 방어를 구분한다.
- 바르칸 체력이 2/3보다 높을 때에는 먼저 보스 공격을 안내하고, 약화되어 후퇴하면 쇠사슬 장치를 안내한다. 지역 밖에서는 보관된 성채 전투 상태를 조회한다.
- 주변 지점 말풍선은 챕터가 제공하는 실제 입력을 사용한다. 지휘 인장을 Space로 파괴할 수 있는 것처럼 안내하지 않는다. 야영지는 회복과 복귀 등록을 표시한다. 이전 지점 설명은 180 단위 안에서만 유지하며 다른 지점에 접근하면 새 입력 안내를 표시한다.
- 활성 지역에서 300 단위 이내의 적이 공격을 준비하면 말풍선을 잠시 숨겨 위험 표시를 우선한다. 상호작용 입력 자체를 차단하지 않는다.
- 목표 패널은 가까이 있을 때 행동을 표시하며 방향을 지면 투영에 맞춘다. 긴 목표와 단축키는 UTF-8 문자를 손상하지 않고 너비에 맞게 줄인다. K 스킬 안내도 추가했다.
- 챕터 2 일반 필드 오크의 체력을 45에서 기존 스토리 일반 오크와 같은 70으로 맞춘다. 공통 조정값은 `LevelTuning::OrcHealth`다. 지역별 `MapDefinition::fieldEnemyHealth`를 초기 생성과 재생성에 사용한다. 무리 수·배치·피해량·감지·재생성 시간은 그대로다. 수치는 사용자 확정 세계 설정이 아닌 구현 조정값이다.

## 파일 책임과 연결

| 파일 | 책임 |
| --- | --- |
| [CombatCueView](../../SimpleGame/src/ui/CombatCueView.cpp) | 공격 경고 원과 준비 막대. 챕터의 적/보스 표시에서 호출 |
| [HudTextLayout](../../SimpleGame/src/ui/HudTextLayout.h) | 렌더러 글자 너비로 UTF-8 문장 축약 |
| [ChapterGoals](../../SimpleGame/src/chapters/ChapterGoals.cpp) | 스토리 상태에 따른 목표 위치·제목·행동 |
| [GameSessionWorld](../../SimpleGame/src/app/GameSessionWorld.cpp) | 월드 좌표 변환과 소유 챕터별 상호작용 안내 |
| [PrototypeWorld](../../SimpleGame/src/app/PrototypeWorld.cpp) | 현재 주변 지점과 설명 말풍선 표시 선택 |
| [FieldPopulation](../../SimpleGame/src/combat/FieldPopulation.cpp) | 지역 정의에서 필드 체력을 읽고 재생성에도 유지 |
| [VisualPlaytest](../../SimpleGame/src/verification/VisualPlaytest.cpp) | 숨겨진 렌더링 컨텍스트, 자동 이동/전투, 장면과 CSV 기록 |

`Chapter::Goal → GameSession::TrackedGoal → ExpeditionView`가 목표 안내를 연결한다. `Chapter::InteractionPrompt → GameSession::LandmarkPrompt → InteractionBubbleView`가 실제 입력을 안내한다. 일반 AI와 경고는 `FieldEnemy`의 공격 거리·준비 시간을 공유한다. 새 전투 매니저는 추가하지 않았다.

C++17 `std::optional`은 없는 목표를 표현하고, `std::vector`는 A* 경유점과 캡처 버퍼를 보관한다. `std::filesystem`은 로컬 산출물 경로를 처리하며 `std::clamp`는 준비 진행과 색상을 제한한다. 검증 전용 친구 클래스가 실제 월드 상태를 읽되 일반 플레이용 상태 변경 API를 추가하지 않는다.

## 자동 플레이 재현

프로젝트 루트에서 빌드한 실행 파일로 다음을 실행한다.

```text
x64/Debug/SimpleGame.exe --playtest-visual output/combat-guide-polish/recheck
```

이 모드는 표시되지 않는 창에서 게임 렌더러를 실행한다. 사용자 입력을 주입하거나 포커스를 바꾸지 않는다. 배급소까지 A* 경유점을 실제 이동 처리로 따라가며 상호작용·농가 전투·패배·재도전·세계 지도를 검사한다. 보스 준비 장면은 스킵과 공개 스토리 이벤트로 전투 상태를 준비한 뒤 실제 `Update`가 공격을 시작할 때 캡처한다. 보스까지 자연스럽게 처음부터 진행한 플레이로 해석하지 않는다. 별도의 오크 장면은 표시만 비교하는 합성 개체다.

`combat-trials.csv`에는 챕터, 시드, 직업, 회피 정책, 시뮬레이션 시간, 받은 피해, 최저 체력, 처치 수, 패배 여부를 기록한다. 시드 743/911/1201 × 마법사/기사 × 접근 공격/공격 준비 시 후퇴 × 챕터 1/2의 24개 조건이다. 공격과 스프린트는 실제 월드 갱신 경로를 사용한다. 회복 전리품과 레벨 상승 회복도 적용되므로 받은 피해와 최저 체력은 다른 지표다. 가장 가까운 적을 연속 추적하는 정책이며 한 무리만의 고정 전투 시간이 아니다. 최대 60초에서 종료하므로 제한 시간 종료도 모든 적 처치와 구분해야 한다.

초기 탐색 캡처는 시드 고정 위치를 바로잡기 전 자료다. 밀도·난이도 비교에는 고정 시드가 확인된 `output/combat-guide-polish/balance-before/combat-trials.csv`와 이후 결과만 사용한다.

## 한계

자동 정책과 대표 장면 확인은 사람이 자유롭게 조작하는 체감 검토를 대체하지 않는다. 스킬 조합·장시간 탐험·모든 해상도·모든 보스 진행 분기를 직접 플레이한 것은 아니다. Chapter 3 구현은 이번 작업에 포함하지 않았다.

## 최종 검증 결과

- Debug x64 빌드 성공. 기존 Chapter1View의 int→float 경고 2개는 남아 있다.
- `--verify-open-world`, `--verify-chapter1`, `--verify-chapter2-foundation` 통과. 농가 목표를 실제 전투 중심으로 변경했으므로 재방문 검사의 기대 위치도 해당 중심으로 갱신했다.
- 숨겨진 자동 플레이와 13개 장면 캡처 완료. 배급 상호작용·실제 이동·제자리 전투 패배·보존 후 재도전·지도·오크 경고·바르칸 3개 공격·960×540 UI를 확인했다.
- 24개 접근 공격/후퇴 조건은 모두 생존했다. 챕터 1은 6마리 연속 전투에서 6.80~9.50초, 피해 8~24였다. 제자리 공격 정책은 별도 시나리오에서 2마리 처치 후 패배했다.
- 챕터 2의 12개 조건 평균은 조정 전 38.882초/피해 6.667/처치 24.0, 조정 후 43.117초/피해 10.667/처치 24.0이다. 개별 경로·처치 수는 달라지므로 같은 적 수에 대한 순수 처치 시간 비율로 해석하지 않는다. 후퇴 정책이 모든 조건에서 피해를 줄이지 않았으며 일반적인 사람의 회피 성능을 나타내지 않는다.
- 최종 로그와 장면은 로컬 `output/combat-guide-polish/final-verified/`에 있다. 코드/프로젝트 경로 117개·include 276개와 문서 링크 557개 검사에서 누락이 없었다. 신규/변경 C++에는 프로젝트 clang-format을 적용했다. FPS 개선이나 GPU 성능 향상을 측정한 작업은 아니다.
