# Chapter 1 Implementation Audit

## 구현됨

- MAP-001, MAP-002, MAP-003 및 MAP-003-B 상태를 `TutorialLayout`/`LevelMap`의 한 코드 경로에서 관리한다.
- 배급 보수, 선택 기부, 경보, 농가 습격, 세 가지 증거, 북쪽 이동을 `Chapter1Director`에 연결했다.
- 얕은 수레 흔적·깊은 수레 흔적·곡물·긁힌 나무껍질·젖은 밧줄 단서와 미끼 길 매복을 구현했다.
- 수송대 전투, 수레 고정핀 상호작용, 포로 구출, 폐광 송장 확보 및 맵 이동을 구현했다.
- 폐광 정문/배수로 진입, 병참 조사, 승강기 선택, 그르마 1:1 결투를 구현했다.
- 그르마 갑옷 파괴·다리 부상, 치료병·투척병 지원, 명령 종 3개, 증원문 유지 입력, 전략 성공을 구현했다.
- 전략 성공 후 플레이어 전투 불능 → 여성 용사 등장 → 35초 결과 연출 → 그르마 처치 순서를 유지한다.
- 지휘 장부·용사 대화·Chapter 2 회색벽 요새 경로를 구현했다.
- `Chapter1State`에 문서의 진행 상태와 TRG 상태를 명시적으로 보관한다.
- 기존 공용 고블린·주민·치료병·지휘관·용사 이미지는 경로와 알파를 확인한 뒤 선택적 렌더링 후보로 연결했다. 미확정 제작 에셋은 임시 도형 fallback을 유지한다.

## 검증

- `clang-format` 적용 및 `git diff --check`: PASS.
- `.vcxproj`/`.filters`의 Chapter 1 코드 등록과 XML 파싱: PASS.
- Debug x64 MSBuild: BLOCKED. MSBuild가 사용자 로컬 Windows SDK 검색 위치에 접근하는 단계에서 권한 오류(MSB4184)를 반환했다. 자동 승인 검토 사용량 제한으로 권한 상승 재시도도 실행되지 않았다.
- 실행·시각 플레이 검증: 빌드 산출물이 없어 수행하지 못했다.

## 에셋 제한

공식 manifest에서 Hero, Gruma, Generic NPC, Healer, 기능성 소품은 `SPEC_READY`이며 실제 배포 검증 상태가 아니다. 기존 폴더의 PNG는 알파와 크기를 정적으로 확인했지만, 프레임 의미·게임 내 품질·배치까지 검증했다고 표시하지 않는다. SmallKnight 폴더와 Common Goblin 파일은 수정하지 않았다.

## 알려진 구현 가정

정밀 좌표, HP, 공격력, 증원 주기, 증원문 유지 시간, 보스 payoff 시간은 구현 상수다. 기존 저장/체크포인트 시스템을 추가하지 않았고 패배 시 현재 Chapter 세션의 입구 재시작을 사용한다. Chapter 2 본문 맵은 만들지 않고 Chapter 1 종료 경계만 제공한다.
