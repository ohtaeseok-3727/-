# 스킬 시스템 구현·테스트 안내

2026-10-13 마법사 필살기 연결은 [마법과 검의 노래](MAGE_SWORD_SONG.md)를 따른다.

> 아래 초기 구현 기록의 미연결·임시 데이터 설명은 당시 상태다. 현재 마법사 연결은 [미리보기 스킬 연결](../design/12-skill-integration.md), 2026-10-08 기사 3종의 실제 공격·패시브 연결은 [기사 스킬 런타임](KNIGHT_SKILLS.md)을 따른다.

## 마나 회복 — 2026-11-05

사용자 확정은 [기획의 마나 회복 규칙](../design/02-world-and-player.md#마나-회복--사용자-확정-2026-11-05)을 따른다. 두 직업 모두 기본 공격 명중 시 1·2타 5%, 3타 30%, 자연 회복은 최대 MP의 초당 1%다.

- [EnemySystem::Strike](../../SimpleGame/src/combat/EnemySystem.cpp)는 `MeleeStrikeResult`에 적 명중 여부와 기존 처치 위치 목록을 함께 반환한다. 살아 있는 적에 대한 기존 범위·방향·벽 가림 검사를 통과해야 명중으로 센다. 처치하지 못한 공격과 처치한 공격 모두 대상이다.
- [GameSession::Strike](../../SimpleGame/src/app/GameSession.cpp)는 활성·인접 지역의 명중 여부를 합쳐 회복을 한 번 적용하고 기존 경험치·전리품 처리를 유지한다. [BasicAttack::ConsumeHits](../../SimpleGame/src/combat/BasicAttack.cpp)가 각 타격 시점을 한 번 전달한다. 장치만 공격하거나 허공·시체를 공격한 경우와 스킬의 투사체·범위 피해에는 이 회복을 적용하지 않는다.
- [PlayerProgression](../../SimpleGame/src/player/PlayerProgression.cpp)의 `RecoverMana`가 정수 이하 회복량을 `double`로 누적하고 최대 MP에서 제한한다. `UpdateManaRecovery`는 `GameSession::Update`에서 전달받은 게임 시간에 현재 최대 MP의 1%를 곱한다. 새 게임·디버그 레벨 설정·완전 회복은 소수 누적도 초기화한다.
- 구현 가정: 한 타격으로 여러 적 또는 경계 양쪽의 적을 맞혀도 회복은 타격당 한 번이다. 기본 공격의 비율 기준은 타격 순간의 최대 MP이며 해당 처치로 레벨이 오르기 전 값을 사용한다. 최대 MP를 넘는 회복을 비축하지 않는다. 자연 회복은 전투·이동 중에도 적용하되 기존 시뮬레이션이 멈추는 메뉴·일시정지·포커스 상실·패배 중에는 진행하지 않는다. 체력이 0인 스토리 연출 중에도 회복하지 않는다.

검증 범위: 소스의 타격 이벤트, 지역별 명중 집계, 최대치·소수 누적, 정지·패배 경로와 기존 호출부를 정적으로 검토했다. [GameSessionVerification](../../SimpleGame/src/verification/GameSessionVerification.cpp)의 기존 챕터 검증 경로에 두 직업의 자연 회복, 비정수 회복, 최대치와 초과 비축 방지, 완전 회복 초기화, 잘못된 시간, 빗맞힘, 5/5/30% 명중 회복, 다중 적 1회 적용, 스킬·시체 제외, 패배 중 정지를 검사하는 회귀 소스를 추가했다. 사용자 지침에 따라 빌드·게임·C++ 검증 프로그램은 실행하지 않았다. 실제 HUD의 증가와 체감 밸런스는 사용자 실행 확인이 남아 있다.

## 확정 설정

- `K`로 스킬 창을 열고 닫는다.
- 하단 HUD에는 `A S D F Q W E R` 순서의 8개 퀵슬롯을 화면 하단 중앙에 표시한다.
- 현재 직업의 스킬만 표시하고, 요구 레벨 미달·패시브는 등록할 수 없다.
- 스킬 창 아이콘을 끌어 슬롯에 놓으면 등록하고, 기존 슬롯은 교체한다.

## 파일과 역할

- `SkillCatalog`: 직업별 스킬 정의의 저장소다. 현재 이름·MP·쿨타임·계수는 `demo_` ID와 “임시” 이름으로 구분한 데모 데이터다.
- `PlayerSkills`: 플레이어 직업의 목록과 레벨·액티브 사용 가능 여부를 판단한다. 스킬 포인트나 구매 규칙은 추가하지 않았다.
- `SkillQuickSlots`: 키-슬롯 매핑과 한 슬롯의 한 스킬 규칙을 관리한다.
- `SkillDragController`: 드래그 선택 및 마우스 위치만 보관한다.
- `SkillView`: 읽기 전용 HUD·스킬 창 렌더링을 담당한다.
- `SkillSystem`: 위 모듈을 조정하고 MP·쿨타임 검사 뒤 사용 요청을 만든다. 실제 공격 판정은 만들지 않는다.

`PrototypeWorld`는 시스템을 갱신하고 입출력을 전달하며, `SimpleGame`은 GLUT 키·마우스 에지를 전달한다. `PlayerProgression`은 현재 MP와 `SpendMana`를 제공한다. 같은 스킬을 여러 슬롯에 넣었을 때 쿨타임은 스킬 ID별로 공유한다.

## 실행 흐름

1. `K`를 누른 뒤 사용 가능한 액티브 아이콘을 왼쪽 버튼으로 누른다.
2. 드래그 중인 아이콘이 마우스를 따라가며, 슬롯 위는 강조된다.
3. 슬롯에서 버튼을 놓으면 `SkillQuickSlots`가 해당 ID로 교체한다. 슬롯 밖, 잠긴 스킬, 패시브는 변경하지 않는다.
4. 등록 키의 새 누름은 `SkillSystem::TryUse`로 간다. MP 부족 또는 재사용 대기 실패도 입력을 소비한다.
5. 성공 시 MP와 스킬별 쿨타임만 반영하고, “사용 요청” 알림을 보인다. `SkillUseRequest`는 기존 공식 `공격력 × (공격력 반영 비율 / 100) + STR/INT × 추가 계수`를 순수 계산해 후속 전투 판정에 전달할 확장 지점을 제공한다. 현재는 성장 시스템의 기본 공격력만 사용하며 장비 보너스·피해·투사체·효과는 후속 전투 구현 범위다.

## 입력 충돌 구현 가정

`A/S/D/W`에 등록된 스킬은 그 키가 이동보다 우선하며, 보유 중에도 이동하지 않는다. 비어 있는 해당 슬롯은 기존 WASD 이동을 유지하고 방향키는 일반 플레이 중 이동한다. `E/R`은 스킬 전용이며 빈 슬롯은 아무 동작도 하지 않는다. MP 부족/쿨타임도 기존 행동으로 폴백하지 않는다. 상호작용은 `Space`, 마을 귀환은 `B`이며 `F/Q/E/R`은 스킬 전용이다. 스킬 창을 열면 게임은 자동 정지하지 않지만 이동·Ctrl 공격·스킬 입력은 막힌다.

스킬 창은 공격·이동·스킬 사용을 막지만 월드를 자동 일시정지하지는 않는다. `P`, `I`, `M` 전환과 포커스 이탈은 드래그를 취소한다. 포커스 손실 때 실제로 눌린 키는 키업 전까지 억제하여, 복귀 후 held key가 새 입력으로 실행되지 않게 했다.

## STL과 C++ 사용

`std::vector`는 직업별 가변 스킬 목록, `std::array`는 고정 8 슬롯, `std::unordered_map`은 스킬 ID별 쿨타임의 빠른 조회에 사용한다. `enum class SkillKind`는 액티브와 패시브를 형 안전하게 구분한다.

## 직접 테스트할 항목

1. 마법사와 기사를 각각 선택해 직업별 목록이 달라지는지 확인한다.
2. 레벨 1의 임시 액티브 1·2를 서로 다른 슬롯에 놓고 교체를 확인한다.
3. Lv.3 임시 패시브와 Lv.5 임시 잠금 액티브가 어둡게 보이고 드래그·등록되지 않는지 확인한다.
4. 슬롯 밖 드롭이 등록을 바꾸지 않는지, 드래그 중 슬롯 강조가 보이는지 확인한다.
5. 등록 키 한 번당 알림이 한 번만 나타나는지, 길게 누를 때 반복 요청되지 않는지 확인한다.
6. MP 소모, 부족 알림, 같은 스킬을 중복 등록한 슬롯의 공유 쿨타임을 확인한다.
7. 등록/비등록 WASD, `E/R`, `Space`, `B`, 방향키, Ctrl, I/M/P와 포커스 전환을 함께 확인한다.
8. 창 크기를 바꿔도 하단 중앙 슬롯과 알림이 겹치지 않는지 확인한다. 600×570보다 작은 창은 슬롯을 축소해 유지하고, 스킬 창은 “창을 더 키우세요” 안내만 표시한다.

## 아직 구현하지 않은 영역

실제 스킬 이미지, 확정 스킬명·밸런스·피해 계수, 스킬 포인트·구매·선행조건·저장, 패시브 효과와 공격 판정은 구현하지 않았다. 데이터의 공격력·STR/INT 계수 필드는 기존 피해 공식에 연결할 확장 지점으로 보관하며, 현재 데모 값은 0이라 전투 효과를 만들지 않는다.

## 빌드 결과

실행 중인 기본 EXE를 바꾸지 않기 위해 `Debug|x64`를 `x64\SkillBuild\SimpleGameSkillCheck.exe`로 별도 링크했다. 컴파일과 링크는 경고 0개, 오류 0개로 성공했다. 사용한 도구는 Visual Studio 2022 Community의 `MSBuild.exe`이며 게임 실행은 수행하지 않았다.
