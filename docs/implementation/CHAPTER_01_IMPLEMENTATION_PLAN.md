# Chapter 1 구현 계획과 차이 분석

사용자가 2026-09-21 Downloads/CODEX_CHAPTER_01_IMPLEMENTATION_PROMPT.md의 실행을 요청했다. 이번 요청은 실제 Debug x64 빌드·검증을 포함한다.

## 기준

`_story_scene_production/05_final_chapters/CHAPTER_01_FINAL.md`의 확정 사실 → 최신 C01 리소스/맵 문서 → GAME_DESIGN.md → 기존 코드 순서다. 구형 튜토리얼의 파밍 레벨 목표·베테랑 복귀·전초기지 조사 흐름은 대체한다.

## 조사 결과

- 기존 월드는 C++ 좌표·영역·도로 및 반지름 11 충돌을 사용한다. 타일맵 엔진을 추가하지 않는다.
- 기존 세션에는 경험치·장비·전리품만 있고 Chapter 진행 상태나 실제 맵 전환이 없다.
- 기존 적은 동일 행동의 재생성되는 도형이며 보스·지원·치료 역할이 없다.
- Actor–SceneGraph–SceneRenderer와 기존 저수준 Renderer 배치는 재사용한다.
- 기존 Space 상호작용은 설명만 표시한다. 실제 오브젝트 상태 변경과 유지 입력을 추가한다.

## 실행 계획

1. 세 개의 C01 기본 맵과 C02 진입 경로를 C++ blockout으로 작성하고 지역 내 도로·방·분기·강 충돌을 연결한다.
2. Chapter1State, 진행 Director, Encounter 제어를 분리한다. 문서의 TRG/ENC 번호를 보존한다.
3. 배급·기부·농가 증거·갈림길 단서·수레·포로·송장·폐광 조사와 이동을 연결한다.
4. 그르마 결투·갑옷/다리 손상·병력 지휘·치료병·종 세 개·증원문 유지 입력을 구현한다.
5. 전략 성공 후에만 전투 불능과 여성 용사 payoff(30–45초), 장부·동행·C02 경로를 활성화한다.
6. 기존 이동/공격/인벤토리/스킬/후처리를 연결하고 에셋이 없는 외형은 명시적인 도형 placeholder로 표현한다.
7. 프로젝트 등록, Debug x64 빌드, 자동 게임 로직 흐름/충돌 회귀 검증, 구현 audit를 작성한다. 시각 확인이 불가능하면 해당 항목을 별도로 미검증으로 보고한다.

## 구현 가정

정밀 좌표·피해량·HP·증원 주기·문 유지 시간은 구현 상수다. 구체적인 기획 확정 수치로 취급하지 않는다. 일반 패배 시 현재 맵 입구로 복귀하는 기존 세션식 재시도를 사용하며 새 저장 시스템은 추가하지 않는다.
