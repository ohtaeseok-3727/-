# Esc 시스템 메뉴

2026-09-30 · 브랜치 `codex/escape-settings-menu`

## 사용자 확정 동작

직업 선택 후 Esc로 시스템 메뉴를 연다. 게임 종료, 게임 설정, 챕터 1 스킵, 챕터 2 필드 스토리 스킵은 각각 마우스 왼쪽 버튼으로 클릭한다. 챕터 2 필드 스토리 스킵은 회색벽·협곡을 건너뛰고 성채 입구부터 진행한다.

## 구현 동작과 가정

- 메뉴를 열면 다른 창을 닫고 이동·공격·상호작용·단축키와 게임 시뮬레이션을 멈춘다. 게임으로 돌아가기 버튼 또는 첫 화면의 Esc로 재개한다. 하위 화면의 Esc는 메뉴로 돌아간다. 기존 P 일시정지에서 Esc를 눌러도 메뉴로 전환된다.
- 버튼은 마우스 올림·누름·비활성 상태를 표시한다. 같은 버튼 안에서 눌렀다가 놓아야 실행된다. 창 포커스 상실·크기 변경 시 누름을 취소하며, 메뉴를 닫는 클릭이나 누르고 있던 이동·공격이 게임에 전달되지 않게 한다.
- 게임 설정은 기존 PostSettings의 화면 후처리, 빛 번짐, 가장자리 어둡게, 가장자리 흐림, 밝기 감소/증가와 기본값 복원을 제공한다. 후처리를 끄면 종속 버튼은 비활성화한다. 변경은 즉시 적용되며 이번 실행에만 유지한다. 새 저장 시스템·오디오 설정은 포함하지 않는다.
- 종료와 스킵은 확인/취소 버튼을 거친다. 종료 확인에는 현재 진행을 저장하지 않는다는 안내를 표시한다.
- 챕터 1 스킵은 C01 진행·장부·용사 대화를 완료 처리하고 회색벽 입구로 이동한다. 이미 완료했거나 C02 미리보기로 시작했다면 비활성화한다.
- 챕터 2 필드 스토리 스킵은 C01 완료 후 또는 C02 미리보기에서 활성화한다. 성채 진입 단계 이상에서는 다시 사용할 수 없다. 기존 완료 목표와 진행 중인 선택을 유지하고, 나머지만 **봉화탑 → 작업장 → 수용소** 순서로 완료한다. 이 순서는 스킵용 구현 가정이며 기존 결과 산식을 통해 피해·증원·진입로 조건을 계산한다. 확인 화면에서도 알린다.
- 스킵은 레벨·경험치·돈·장비를 보존하며 체력·마나를 회복한다. 건너뛴 전투에 경험치나 전리품을 지급하지 않는다. 목적지 입구를 복귀 체크포인트로 지정한다. 필드 일반 몬스터는 유지하고 해당 구간의 스토리 적만 퇴장 처리한다. 이 보상·회복 정책은 구현 가정이다.

`Esc → SettingsMenu → 버튼 누름/놓음 → 확인 → GameSession → Chapter → 목적지 적용` 순서다. 게임 설정은 `PostSettings`를 즉시 변경한다. UI는 기존 후처리가 끝난 뒤 마지막에 그린다. 메뉴가 열린 동안 기존 `MenuOpen` 차단 경로를 사용한다.

C++17의 `std::optional<Action>`으로 눌린 버튼의 유무를 표현한다. `std::vector<Button>`은 현재 페이지의 버튼 목록을 렌더와 클릭 판정에 공통 제공한다. `std::clamp`는 밝기를 기존 0.1~5.0 범위로 제한한다. 기존 `std::bitset` 스토리 기록과 선택 결과 계산을 재사용한다.

## 검증 범위

프로젝트 지침에 따라 빌드·게임 실행·C++ 검증 실행은 수행하지 않았다. 변경 코드의 입력 전달, 완료 조건, 월드/지역 좌표와 재실행 방지를 정적으로 검토했다. 프로젝트/필터 XML, 새 파일 4개 등록, 관련 로컬 include 50개, 문서 링크 78개, 변경 C++ 12개의 clang-format 및 공백 검사에서 오류가 없었다. 실제 화면 크기별 배치와 플레이 결과는 사용자 빌드 후 확인이 필요하다.

수동 확인 항목: Esc 열기/닫기와 P 전환, 버튼 바깥에서 놓기·포커스 상실 후 취소, 메뉴 중 공격/이동 차단, 그래픽 설정 즉시 반영, 스킵 취소·완료 버튼 비활성화, C01 스킵 후 회색벽 브리핑, C02 일부 목표 선택 후 스킵의 결과 보존, 성채 진입로 선택부터 바르칸까지의 정상 진행, 이동 후 패배 시 새 체크포인트 복귀.

## 챕터 3까지 확장 — 2026-10-20

사용자 확정 범위는 챕터 3까지 스토리 건너뛰기를 제공하는 것이다. 기존 챕터 1·챕터 2 필드 스킵을 유지하고 Esc 메뉴에 **챕터 2 전체 스킵**, **챕터 3 전체 스킵**을 추가했다. 모두 확인/취소 화면을 거친다.

아래 세부 동작은 기존 스킵 정책을 확장한 구현 가정이다.

- 챕터 2 전체 스킵은 챕터 1 완료 또는 챕터 2 미리보기에서 활성화한다. 성채·바르칸·구호지 보고까지 완료하고 챕터 3 기록관 기념홀 입구로 이동한다. 챕터 2 결과를 챕터 3에 전달한다.
- 기존 목표 선택 순서와 진입로는 보존한다. 남은 필드 목표는 기존 필드 스킵의 순서로 처리한다. 미선택 성채 진입로만 수로로 채운다. 교량·보급 손실은 정상 보스전 완료와 같이 최소 1이며 기존 더 큰 피해는 줄이지 않는다.
- 챕터 3 전체 스킵은 챕터 2 완료 또는 챕터 3 미리보기에서 활성화한다. 조사·세라드 생존 제압·원본 회수·분산 보관·증언·왕실 심의·제한 조사 승인을 완료 처리하고 아르겐 입구로 돌아간다. 챕터 4는 미구현이므로 새 지역으로 이동하지 않는다.
- 이미 선택한 추가 사본 보관처를 보존하고, 미선택인 경우 성직자 공동체를 기본값으로 쓴다. 이 기본값은 스킵용이며 스토리의 정식 선택을 확정하는 규칙이 아니다. 광역 수배와 전쟁 발단 확인 플래그는 기존 결말처럼 0이다.
- 레벨·경험치·금화·장비·처치 수는 보존하고 체력·마나를 회복한다. 챕터 3의 미수령 제한 보급도 보상 없이 처리하여 스킵 후 금화를 추가 수령할 수 없게 한다. 이미 받은 보상을 회수하지 않는다.
- 건너뛴 챕터의 스토리 적만 보상 없이 퇴장시키며 일반 필드 몬스터는 유지한다. 챕터 2 전체는 성채 적과 바르칸까지, 챕터 3은 세라드 전투 객체까지 정리한다. 목적지를 복귀 체크포인트로 지정하고, 완료 후 해당 스킵은 비활성화한다.

`SettingsMenu`의 클릭·확인 → `PrototypeWorld`의 명령 전달과 공격·발사체·카메라 정리 → `GameSessionSkipping`의 선행 조건·목적지 검증 → `ChapterSkipping`의 챕터별 상태 변경 → 스토리 적 정리·지역 이동·이력 전달 순서다. `GameSession::StorySkip` 열거형으로 기존 두 종류와 전체 스킵 두 종류를 구분한다. `std::bitset`으로 완료 기록을 채우고 `std::optional`로 기존 진입로·추가 보관처 선택을 보존한다.

정적 검토와 서식·문서 인덱스 검사를 수행한다. [Chapter3Verification.cpp](../../SimpleGame/src/verification/Chapter3Verification.cpp)에 선행 조건, 순차 스킵, 기존 선택 보존, 보상 불변, 회복·체크포인트, 재실행 차단, 스킵 후 보급 중복 방지, 챕터 2·3 미리보기 경로의 회귀 검사 소스를 추가했다. 프로젝트 지침에 따라 빌드·게임·회귀 검사는 실행하지 않았다. 실제 메뉴 배치와 플레이 결과는 사용자 실행 확인이 필요하다.
