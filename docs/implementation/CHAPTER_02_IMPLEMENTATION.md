# Chapter 2 구현 현황

2026-09-24 · 브랜치 `codex/chapter2-gameplay-v2`

## 기준과 연결

확정 스토리는 `_story_scene_production/05_final_chapters/CHAPTER_02_FINAL.md`의 「협곡의 미끼」다. C01 장부와 용사 대화 후 출구가 일반 등록된 C02로 연결된다. MAP-004 회색벽 → MAP-005 협곡 → MAP-006 성채 → 협곡 사후 확인 순서다. `--preview-chapter2`는 시작 위치만 C02로 바꾸며 진행 조건을 생략하지 않는다.

## 구현한 진행

- 회색벽: 브리핑, 흔적 조사, 감시초소 전투와 일정표, 정면 지원, 측면 신호병, 봉화 확인과 추격 중지. 정면 지원 뒤 사망해도 신호병 전투를 다시 만든다.
- 협곡: 위험을 읽고 세 목표를 하나씩 선택한다. 먼저 선택한 목표는 3단계, 다음은 2단계, 마지막은 1단계다. 봉화는 중계 장치 차단, 작업장은 폭발 예고를 피하며 폭약·지지대 확보, 수용소는 문 해제 후 추가 단계에서 적 처치와 대피 지점 8초 방어다. 장치 위치는 화면 표식으로 안내한다.
- 결과: 봉화 지연은 정예 증원, 작업장 지연은 교량·보급 손실 및 보스 폭발 간격, 수용소 지연은 민간 피해와 예배당 정보에 반영한다. 손실 수치는 인원수가 아닌 상대적인 단계다.
- 성채: 가능한 진입로 선택, 경계 전투, 10초 탁본 조사, 폭파선·우회문 처리, 합류 신호. 용사를 붙잡는 전열은 위치를 유지하는 스크립트 병력이며 합류할 때 죽이지 않는다.
- 바르칸: 휘두르기, 목표 위치를 미리 고정하는 점프 내려찍기, 밀침과 자신의 공격속도 증가를 갖는 전투의 함성. 공격과 폭발 예고를 그린다. 작업장 지연에 따라 폭발 간격이 달라지며 교량 폭파 장치에서 Space를 유지해 차단한다. 체력 2/3부터 북쪽으로 후퇴하며 서쪽 쇠사슬로 퇴로를 막는다. 체력 1/3 이하에서 용사가 자세를 무너뜨리고 플레이어가 동쪽 지휘 인장을 공격하면 합동 마무리를 진행한다.
- 사후: 교량 근처로 귀환해 구호지의 손실과 생존자를 확인하고 탁본을 검토한다. 피난민 대다수 생존과 교량·보급 일부 손실을 유지하며 다음 기록 조사 목표와 결과 플래그를 남긴다.

## 파일 책임과 실행 흐름

`Chapter2` 하나가 진행 상태와 전투를 소유한다. `Chapter2.cpp`는 이벤트·선택·상호작용·결과, `Chapter2Combat.cpp`는 목표 단계·용사·보스·피해, `Chapter2Map.cpp`는 지도와 장치 좌표, `Chapter2View.cpp`는 장치·위험 표식·연출을 담당한다. `Chapter2Sprites`는 텍스처를 한 번 로드해 재사용한다. 추가 매니저 클래스를 만들지 않았다.

`GameSession::Update` → `Chapter2::Update` → 기존 `EnemySystem`과 용사·보스 처리 → 피해/밀침과 보상 전달 → `SceneGraph`에 동적 표식 등록 → 렌더링 순서다. 일반 오크는 공통 AI, 바르칸과 용사를 붙잡는 전열만 스크립트 제어다. 용사 처치는 `ConsumeScriptDefeats`로 한 번 소비해 기존 경험치·전리품 경로로 전달한다. 퇴장 처리에는 처치 보상을 주지 않는다.

C++17의 `std::optional`은 미선택 목표·진입로를, `std::array`와 `std::bitset`은 고정된 세 목표와 이벤트를 표현한다. `std::vector`는 적·경로·처치 전달에 사용하며, `std::clamp`로 보간 범위를 제한한다. 결과 `unordered_map`은 후속 챕터에서 플래그를 조회할 때 만든다.

## 구현 가정과 남은 한계

체력, 피해, 거리, 조작·방어 시간, 봉화/작업장 장치 위치와 단계, 진입로 조건은 밸런싱을 위한 구현 가정이다. 사용자 확정 설정으로 승격하지 않았다. 함성은 현재 플레이어와 용사를 밀고 바르칸 자신의 속도를 높인다. 세부 적용 대상은 사용자 확정 전 조정 가능하다.

환경·민간인·장치는 기존 Renderer 도형 표현이며 전용 완성 스프라이트가 아니다. 봉화의 은신 감지 시스템, 실제 인원별 피난민 이동 AI, 실시간으로 다른 지역 피해가 증가하는 시뮬레이션은 구현하지 않았다. 미처리 지역 악화는 완료 순서 기준이다. 결과는 세션 메모리에 보존하며 디스크 저장/불러오기 및 Chapter 3 본편은 범위 밖이다. 성채 병력을 붙잡는 연출은 독립 NPC 대 NPC 피해 시뮬레이션이 아니다.

## 확인 범위

빌드·게임 실행·C++ 검증 실행은 사용자 지침에 따라 수행하지 않았다. 이번 변경은 소스 정적 검토, clang-format 검사, 프로젝트 XML과 파일 등록, 공백 검사를 대상으로 한다. 이전 버전의 빌드 성공을 이번 변경의 검증으로 간주하지 않는다.

`Chapter2Verification.cpp`에는 6개 선택 순서의 실제 목표 Update/장치 완료, 재시도 신호병 복구, 공동 처치 보상 중복 방지, 이벤트 순서, 지도 연결 검사를 작성했다. 전투를 빠르게 끝내는 테스트 픽스처이며 실제 플레이 밸런스나 화면 품질 검증은 아니다. C01 검증도 챕터 전환 후 보존된 C01 상태를 조회하도록 수정했다.
