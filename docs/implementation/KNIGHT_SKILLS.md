# 기사 스킬 런타임 연결

2026-10-12 추가된 네 번째 스킬은 [궁극기 천단참](CHEONDAN_ULTIMATE.md)을 따른다.

## 적용 수치와 사용 방법

2026-10-08 사용자가 지정한 수치다. 이전 기사 임시 4개 항목을 실제 스킬 3개로 교체했다.

| 스킬 | 습득 | MP | 쿨타임 | 효과 |
| --- | --- | --- | --- | --- |
| 연속 찌르기 | 3 | 4 | 5초 | 1회당 공격력 × 0.70 + STR × 0.5, 시간차 6회 |
| 검기 상인 | 5 | 0 | 없음 | 공격력 +20%, 기본 공격·스킬 범위 +30%, 자동 패시브 |
| 검기 발산 | 5 | 10 | 10초 | 공격력 × 1.50 + STR × 1.0, 적 관통, 검기 상인 필요 |

게임을 다시 빌드한 뒤 기사로 시작한다. `K`에서 연속 찌르기·검기 발산 아이콘을 하단 슬롯으로 드래그하고 창을 닫아 해당 키로 사용한다. 패시브는 등록하지 않으며 Lv.5부터 자동 적용된다. 기존 개발 단축키 `1`로 현재 직업을 Lv.20으로 올리고 HP/MP를 회복할 수 있다. 시작 화면의 `1`은 마법사를 선택하므로 기사 선택 `2` 이후에 누른다.

MP 부족·미습득·쿨타임 중에는 발동하지 않는다. 같은 스킬을 여러 슬롯에 넣어도 쿨타임은 공유한다. 기본 공격 중·스킬 동작 중·메뉴·일시정지·패배·이벤트 잠금에서는 새 스킬을 시작하지 않는다.

## 모듈과 실행 흐름

| 파일·클래스 | 책임 |
| --- | --- |
| [SkillCatalog](../../SimpleGame/src/player/SkillCatalog.cpp) | 스킬 이름, 레벨, MP, 쿨타임, 피해 계수와 공격 수 |
| [PlayerSkills](../../SimpleGame/src/player/PlayerSkills.cpp) | 기사 전용·레벨·액티브 조건과 검기 상인 선행 조건 |
| [PlayerProgression](../../SimpleGame/src/player/PlayerProgression.cpp) | 패시브 활성 여부, 장비 포함 유효 공격력, 범위 배율 |
| [SkillSystem](../../SimpleGame/src/player/SkillSystem.cpp) | MP·쿨타임 처리와 발동 시 피해 계산 |
| [KnightSkillData](../../SimpleGame/src/combat/KnightSkillData.h) | 미리보기 프레임·기준점·알파 경계·시간차·범위 데이터 |
| [KnightSkills](../../SimpleGame/src/combat/KnightSkills.cpp) | 한 번의 캐릭터 동작, 6개 찌르기 공격 객체 또는 독립 이동 검기, 개별 피격 기록 |
| [KnightSkillView](../../SimpleGame/src/ui/KnightSkillView.cpp) | 캐릭터 동작, 찌르기·검기 효과, 검 위치를 따르는 패시브 오라 |
| [PrototypeWorld](../../SimpleGame/src/app/PrototypeWorld.cpp) | 입력·갱신·중단·지역 이동과 화면 객체 등록 |
| [GameSession](../../SimpleGame/src/app/GameSession.cpp), [EnemySystem](../../SimpleGame/src/combat/EnemySystem.cpp) | 투사체 이동 구간 판정, 지역 좌표 변환, 처치·경험치·전리품 |
| [SceneRenderer](../../SimpleGame/src/rendering/SceneRenderer.cpp), [Renderer](../../SimpleGame/src/rendering/Renderer.cpp) | 깊이 정렬, PNG 캐싱, 원본 시트 일부 영역과 좌우 반전 표시 |

입력 → SkillSystem의 자원·조건 검사 → 발동 시 피해 저장 → KnightSkills의 시간차/이동 갱신 → GameSession의 적·스토리 오브젝트 판정 → 기존 보상 처리 순서다. 화면은 같은 공격 객체의 위치·시간과 프레임 데이터를 읽는다.

`std::array`로 6개 이벤트와 4개 프레임을 고정 보관하고 `std::vector`로 현재 공격 객체를 관리한다. `std::unordered_set<uint64_t>`는 공격 객체마다 이미 맞은 대상을 기억하여 한 이펙트가 매 프레임 같은 적을 다시 때리지 않게 한다. 6개 찌르기는 각자 집합을 가지므로 모든 효과와 겹치는 적은 최대 6회 맞는다. `std::optional`은 별도 시선 검사 원점이 있는 기사 공격과 기존 마법사 경로를 구분한다. PNG는 기존 Renderer 캐시에 한 번 올린 뒤 재사용한다. 자동 생성 CombatVisualData는 수정하지 않았다.

## 판정과 수치 해석

- 찌르기 캐릭터 모션은 610ms 1회다. 효과 시작은 180/210/240/270/300/330ms, 효과 수명은 각각 145ms다. 같은 수평 각도에 미리보기의 불규칙한 가로·세로 오프셋을 적용한다.
- 찌르기 사거리를 별도 고정 상수로 만들지 않았다. 원본 효과의 각 프레임에서 알파 32 이상인 픽셀 경계를 측정해 투명 여백을 제외한 사각형을 만들었다. 화면과 판정이 같은 피벗·배율을 사용한다. 픽셀 단위 충돌은 아니며 기존 적 몸통 상자(가로 반폭 16, 세로 반높이 25)와 겹치면 맞는다. 알파 문턱 32와 상자 근사는 구현 선택이다.
- 검기는 360ms에 발사하고 캐릭터는 680ms에 동작을 마친다. 검기는 420ms 동안 비행해 발동 후 780ms에 소멸한다. 미리보기 기본 이동 거리 `840 × 0.51 = 428.4`는 월드 단위로 유지한다. 패시브가 필수이므로 실제 이동 거리는 `428.4 × 1.3 = 556.92`다. 420ms를 유지하여 실제 속도는 1326 월드 단위/초다.
- 효과 이미지 크기·생성 위치는 미리보기 기사 0.61 대비 실제 기사 `0.45 × 0.32 = 0.144` 비율로 환산한다. 범위 +30%는 기본 공격 거리, 액티브 효과 크기·생성 거리·판정 폭·검기 이동 거리에 함께 적용한다. 캐릭터 본체 크기는 키우지 않는다. 범위는 면적 30%가 아닌 선형 크기 30% 증가로 해석했다.
- 유효 공격력은 `(성장 공격력 + 장비 공격력) × 1.2`다. 이 값에 각 스킬 비율을 곱한 뒤 STR 추가항을 더하고 최종 1회 피해를 반올림한다. STR 항에 패시브를 두 번 적용하지 않는다. 마법사와 패시브 이전 기사의 기존 기본 공격 정수 처리도 유지한다.
- 검기는 적을 관통하되 같은 적은 한 번만 맞힌다. 지형 통과는 승인된 사항이 아니므로 기존 발사체처럼 지형에서 멈춘다. 생성 위치까지의 길 및 대상까지의 시선 경로를 검사한다. 공격 중 경직은 기존 적 인터럽트 규칙을 재사용한다.
- 찌르기 짧은 단계는 최대 1/120초 단위로 갱신해 큰 프레임 간격에도 중간 이벤트를 건너뛰지 않는다. 검기의 이동 구간 전체를 검사하고 지형은 4단위 이하 간격으로 확인한다.
- 챕터 1 지휘종도 기사 스킬당 중복 피해를 막고 기존 파괴 이벤트를 호출한다. 종 ID는 uint64 최상위 3개를 예약하고 적의 지역별 ID와 구분한다. 챕터 2 지휘 인장도 기존 파괴 조건을 따른다.
- 메뉴·포커스 이탈 일시정지에는 스킬 시간과 쿨타임을 멈춘다. 직업 선택·귀환·스토리 스킵·맵 전환·패배·이벤트 조작 잠금에서는 남은 스킬을 제거한다. 취소된 스킬의 MP와 쿨타임은 환불하지 않는다. 발동 중 레벨이 변해도 이미 발사된 공격은 발동 당시의 피해·범위를 유지한다.

## 자산과 알려진 시각적 한계

[런타임 자산 안내](../../SimpleGame/Assets/Characters/Skills/Knight/README.md). 원본 PNG 4개를 바이트 그대로 복사했으며 이미지 생성·리터칭은 하지 않았다. 빌드의 기존 Assets 복사 대상에 포함된다.

기존 v1은 사용자가 선택한 미리보기 시안이다. 원본에 기록된 비율·팔레트 완성도 검증 미완료, 검기 발산 동작이 찌르기처럼 보이는 점, 발사 프레임에 검기가 포함된 점은 그대로 남아 있다. 이번 코드 연결이 시안의 시각적 문제까지 해결했다는 의미는 아니다. 오라는 자세별 근사 검 연결점을 사용하므로 실제 게임 화면에서 위치 점검이 필요하다. 새로운 검 베기 코드 효과 v3는 별도 미리보기이며 이 스킬 연결에서 기본 공격 효과를 대체하지 않았다.

## 검토와 사용자 검증

정적 검토: C++ 서식, 프로젝트 XML·필터·파일 참조, 기본 클래스/챕터별 새 인자 연결, 원본 PNG 복사 일치와 크기, 시트 프레임 범위, 문서 링크를 확인했다. **빌드·게임 실행·자동 회귀 검사는 수행하지 않았다.** 시각적 연결·실제 피해·프레임 비용은 런타임 미확인이다.

[KnightSkillVerification](../../SimpleGame/src/verification/KnightSkillVerification.cpp)을 추가했다. 사용자가 빌드 후 `SimpleGame.exe --verify-knight-skills`로 레벨 조건·패시브 비등록·피해 계산·MP·공유 쿨타임·시간차·수명·범위·관통 재피격 방지를 검사할 수 있다. 이 명령은 일반 게임 창을 열기 전에 검사를 실행한다.

직접 확인할 흐름은 Lv.2/3/4/5 경계, MP 3/4와 9/10, 좌우 찌르기의 동일 적 6회, 검기의 복수 적 관통·벽 차단, 패시브 이전/이후 기본 공격 거리, 스킬 중 메뉴 열기/닫기, 귀환·사망·지역 이동 후 잔류 공격 제거다. 기존 챕터 1·2·오픈월드 회귀도 함께 확인한다.


## 2026-10-08 보행 오라 위치 수정

이동 8프레임 전체에 첫 프레임의 검 연결점 (149,374)을 적용해 아래쪽 시트 행으로 바뀔 때 오라가 9.36 화면 단위 내려가는 문제가 있었다. KnightSkillView::DrawAura가 실제 샘플링된 이동 셀의 행·열로 8개 검 연결점을 선택하도록 수정했다. 기존 스프라이트 피벗·배율·좌우 반전 계산은 유지하며 이미지 파일은 수정하지 않았다. 프레임별 검 연결점은 원본에서 시각적으로 읽은 근사값이다.

정적 좌표 계산에서 보행 연결점의 수직 범위는 9.36에서 1.008으로 줄었다. 남은 차이는 프레임의 검 움직임을 반영한다. 서식·공백을 확인했으며 게임 빌드·실행·화면 확인은 수행하지 않았다.
