# 기사 궁극기 천단참

## 사용

Lv.20 기사로 `K`를 열고 **천단참**을 퀵슬롯으로 드래그한다. MP 30, 쿨타임 60초이며 최종 충격파 피해는 공격력 500% + STR × 5.0이다. 기존 개발 단축키 `1`로 현재 직업을 Lv.20으로 설정할 수 있다. 시작 화면에서는 `2`로 기사를 선택한 다음 사용한다. 새 코드는 다시 빌드해야 적용된다.

## 연출 — 2026-10-13 수정

새 효과는 PNG·스프라이트·Blender 모델 없이 도형과 후처리 셰이더로 직접 그린다. 기존 기사 몸 동작만 재사용한다. 최신 요청에 따라 지면을 향한 원호 내려베기와 전방 폭발을 화면을 향한 사선 베기·잔상·화면 균열로 대체했다.

1. 0–650ms: 휘어진 빛줄기가 검에 모이며 비스듬한 검날이 커진다.
2. 650–820ms: 검날이 관객 쪽으로 짧고 두꺼워지는 원근 표현과 함께 화면의 대각선을 따라 베어 들어온다.
3. 820–1050ms: 베기가 끝난 뒤 화면에 하나로 연결된 거대한 금빛 잔상을 남긴다.
4. 1050–1280ms: 잔상 시작점부터 거친 틈이 열리고 양옆으로 연결된 작은 균열들이 뻗는다. 배경 양쪽이 균열을 따라 어긋난다.
5. 1250ms: 캐릭터 조작을 돌려준다. 균열은 독립된 시간으로 유지되므로 다른 스킬 사용이나 방향 전환이 기존 균열을 재시작·반전하지 않는다.
6. 1500–1890ms: 균열과 배경 어긋남이 사라진다. 귀환·사망·맵 이동 등 기존 Reset 경로에서는 즉시 제거한다.

시간과 화면 배치·두께는 연출 구현값이다. 화면 폭의 19%/84%, 높이의 13%/91%를 잇는 선을 사용하고 왼쪽 시전은 수평 반전한다. 화면 비율이 달라도 픽셀 기준 법선으로 배경 분리 방향을 계산한다. 최대 분리량은 1280×720 기준 각 면 13px이며 작은 화면은 비례 축소한다. 파편 객체·효과 이미지·추가 전면 섬광은 없다.

배경은 기존 월드 후처리의 최종 합성 단계에서 직접 샘플링 위치를 바꾼다. UI는 이후에 그려 균열에 의해 변형되지 않는다. HDR 프레임버퍼를 만들 수 없는 환경에서는 배경 변위 없이 균열 도형만 표시한다. 화면 균열은 색상 후처리 설정과 별개인 스킬 연출이다.

[로컬 미리보기](../../output/cheondan-preview-v2/preview.html)와 [미리보기 안내](../../output/cheondan-preview-v2/README.md)에서 재생·슬로모션·좌우 전환·단계 정지로 확인한다. Canvas 수식 이식본이며 게임 실행 캡처가 아니다.

## 범위와 피해

- ‘위로 5배’는 검기 발산 최대 성장 프레임의 아래쪽 경계를 유지하고 위로 높이를 5배 확장하는 것으로 해석했다. 가로 폭은 그대로다. 충격파가 이동하는 동안 이 크기를 유지한다.
- 검기 발산의 기본 이동 거리 428.4를 두 배 한 856.8 월드 단위를 기준으로 한다. 검기 상인의 범위 배율 1.3이 적용된 실제 천단참 이동 거리는 1113.84다. 같은 레벨의 검기 발산 556.92 대비 정확히 두 배다.
- 검기 상인의 공격력·범위 증가가 기존 스킬과 동일하게 적용된다. 공격력 항은 `(성장 공격력 + 장비 공격력) × 1.2 × 5`, 여기에 `STR × 5`를 더해 최종 정수 피해를 반올림한다. 추가 선행 스킬 조건은 만들지 않았다. 현재 자동 습득 규칙상 Lv.20 기사는 이미 패시브를 보유한다.
- 검기와 같은 이동 속도를 유지하여 비행시간을 840ms로 늘렸다. 충격파가 적을 관통해도 같은 적은 한 번만 맞는다. 응축·검 휘두르기·잔상·화면 균열은 추가 피해를 주지 않는다. 기존 이동 판정을 유지한 것은 연출 수정에 밸런스 변경을 섞지 않기 위한 구현 선택이다.
- 월드의 얇은 균열 전진 표식은 `KnightSkillShot::Bounds` 내부에 그린다. 판정은 기존 높이 5배·거리 2배 사각형으로 유지되어 얇은 선보다 넓다. 화면 전체 잔상·균열은 관통 공격의 실제 범위를 나타내지 않는다. 기존 적 몸통 크기도 충돌에 포함된다.
- 벽·장애물 차단, 챕터 타깃·보상, 메뉴 정지, 귀환·사망·맵 이동·이벤트 잠금 시 제거는 기존 기사 스킬 경로를 따른다. 취소 시 MP·쿨타임은 환불하지 않는다.

기존 `SkillSystem`이 MP·쿨타임을 검사한 뒤 KnightSkills에 발동 요청을 보낸다. SceneRenderer → KnightSkillView → CheondanView에서 몸과 월드 효과를 그리고, PrototypeWorld가 화면 합성 전후의 전용 효과를 연결한다. 별도 궁극기 연출 시계는 기존 게임 갱신·정지·Reset을 따른다. Renderer::Begin은 ScreenCut을 매 프레임 초기화해 타 화면으로 변형 값이 남지 않게 한다.

기존 `std::vector` 공격 목록과 `std::unordered_set` 개별 피격 기록을 재사용한다. 도형은 고정 개수 반복문과 스택 값으로 만들며 새로운 파편 컨테이너나 효과 텍스처를 만들지 않는다. `std::clamp`와 `std::min`으로 진행률·수명을 제한한다. 화면 분리용 구조체는 영구 설정과 분리했다.

## 검토와 한계

미리보기 브라우저의 응축·잔상·균열 단계, 좌우 전환과 재생 조작을 확인한다. C++는 정적 검토 대상이며 **게임 빌드·실행, 회귀 실행, 실제 게임 화면과 GPU 성능 확인은 하지 않았다.** Canvas 미리보기 품질은 게임 품질 검증을 대신하지 않는다. 화면 균열 수명·후속 스킬·Reset 회귀 소스를 추가했다.

실제 게임 확인 항목은 좌우 시전, 다양한 창 크기, 균열 중 메뉴 열기, 다음 스킬 발동, 귀환·사망·맵 이동, 후처리 실패 환경이다. 기존 관통 판정과 화면 연출은 서로 다른 좌표계를 쓰므로 화면이 갈라진 곳 전체에 피해가 발생하는 것은 아니다.
