# Actor–SceneGraph–Renderer 구조

2026-09-21 구현. 현재 2.5D 월드의 렌더링 구조를 분리하고 CPU 측 수집·정렬 비용을 줄인다.

## 파일과 책임

- `SimpleGame/src/rendering/Actor.h`, `.cpp`: 위치, 종류, 크기, 원본 엔티티 인덱스를 보관하는 렌더링 Actor. 전투·이동 상태의 소유자는 기존 세션 시스템이며, 동적 Actor는 현재 프레임의 표시용 스냅샷이다.
- `SimpleGame/src/rendering/SceneGraph.h`, `.cpp`: 월드 루트 → 청크 노드 → 정적 Actor 계층과 동적 Actor 분기를 소유한다. 청크 로딩·해제, 가시성 수집, 깊이 순서 병합을 담당한다.
- `SimpleGame/src/rendering/SceneCamera.h`, `.cpp`: 기존 60도 지면 투영과 화면 경계 판정을 담당한다.
- `SimpleGame/src/rendering/SceneRenderer.h`, `.cpp`: 그림자와 Actor의 외형을 기존 Renderer의 도형·스프라이트 명령으로 변환한다. 프레임별 애니메이션 정보는 `SceneFrame`으로 전달한다.
- `SimpleGame/src/rendering/Renderer.h`, `.cpp`: 기존 정점 배치, 텍스처, OpenGL 제출과 후처리를 담당한다.
- `SimpleGame/src/app/PrototypeWorld.h`, `.cpp`: 게임 상태 갱신과 렌더 단계 조립을 담당한다. 개별 월드 객체의 그리기 구현과 청크 저장소는 별도 모듈로 이동했다.

## 프레임 흐름

1. 플레이어 위치와 창 크기에 필요한 청크를 유지한다. 청크 중심·로딩 반경이 같으면 즉시 반환한다.
2. 지면을 그린 뒤 현재 적·전리품·플레이어의 동적 Actor를 수집한다.
3. SceneGraph가 화면 밖 Actor를 제외하고 화면 좌표를 저장한다.
4. 청크 변경 때 정렬한 정적 목록과 이번 프레임의 가시 동적 목록을 병합한다.
5. SceneRenderer가 그림자와 깊이순 Actor를 기존 Renderer에 제출한다.
6. 월드 후처리를 끝낸 후 말풍선·HUD·인벤토리·스킬·지도를 그린다.

## 최적화와 STL 선택

- 정적 Actor는 `std::map`의 청크 노드 안에서 소유한다. 청크 추가가 다른 노드의 주소를 바꾸지 않으며, 순회 순서도 기존 청크 순서와 같다.
- 정적 객체를 매 프레임 복사하지 않고 포인터 목록을 재사용한다. 청크 변경 시에만 `std::stable_sort`로 정렬한다.
- 동적 객체는 화면 밖 대상을 제외한 뒤 `std::stable_sort`한다. 같은 깊이의 적·전리품·플레이어 순서를 유지한다.
- `std::merge`는 두 정렬된 목록을 선형 시간에 합치며 같은 깊이에서는 정적 객체를 먼저 둔다. 기존 전체 stable sort와 같은 본체 제출 순서다.
- 멤버 `std::vector`를 `clear()`하여 용량을 재사용한다. 초기 용량 증가와 `stable_sort`의 임시 메모리 할당까지 없앴다는 의미는 아니다.
- `std::move`로 생성한 청크를 옮겨 Actor 배열의 추가 복사를 피한다.
- 가시 Actor의 화면 좌표를 그림자와 본체가 공유한다.

정적 객체 수를 S, 동적 객체 수를 D, 가시 객체 수를 V, 가시 동적 객체 수를 Dv라고 하면 청크가 유지되는 프레임의 수집·정렬 비용은 대략 O(S + D + Dv log Dv + V)이다. 기존에는 전체 객체를 매 프레임 복사한 뒤 O((S + D) log(S + D)) 정렬을 수행했다.

## 수명과 범위

렌더 큐의 포인터는 SceneGraph 내부 Actor를 빌린다. 삭제·동적 배열 변경 전에 해당 큐를 비우며, 모든 동적 Actor를 추가한 뒤 큐를 만들고 즉시 그린다. 그래프 자체의 복사·이동은 금지하여 내부 참조가 다른 그래프의 Actor를 가리키지 않도록 한다.

현재 SceneGraph는 청크 기반 공간 계층이다. 임의 부모의 회전·크기를 자식에게 상속하는 범용 변환 트리는 이번 구현에 포함하지 않는다. 기존 게임 좌표와 충돌·공격 판정은 유지한다. 가시성 여백도 기존 기준을 유지하므로 향후 더 큰 외형을 추가하면 조정이 필요하다.

이 변경의 주된 대상은 CPU의 객체 수집·정렬 비용이다. GPU 드로 콜 수나 FPS의 개선 수치는 측정하지 않았다. 빌드와 실행은 사용자 지침에 따라 수행하지 않았다.

## 사용자 실행 확인 항목

- 직업 선택 전후 화면과 기사·마법사 이동 및 공격을 확인한다.
- 나무·건물·NPC·적·전리품과 플레이어의 앞뒤 가림을 확인한다.
- 청크 경계를 이동하고 창 크기를 변경한 뒤에도 객체가 유지되는지 확인한다.
- 마을 귀환·사망 후 복귀·일시정지와 말풍선·HUD·후처리를 확인한다.
- 같은 장소·해상도에서 기존 프레임 프로파일러의 FPS와 드로 콜을 비교한다.
