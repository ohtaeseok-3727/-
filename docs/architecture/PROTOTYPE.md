# 렌더링 프로토타입

작성일: 2026-09-08

## 구현 범위

- 생성 화면에서 `1` 마법사, `2` 기사 선택.
- 선택한 기본 직업에 따라 승인된 v2 도트 시안 PNG로 용병을 표시.
- 직업 선택 화면은 기존 시안을 표시하고, 필드에서는 직업별 4방향 걷기 시트를 사용.
- 실제 이동 거리마다 걷기 프레임을 교체하며, 멈추거나 벽에 막히면 현재 방향의
  중립에 가까운 프레임(열 1)을 표시한다. 별도의 정지 애니메이션은 아직 없다.
- 비스듬히 내려다보는 2D 기반 2.5D 필드와 부드러운 추적 카메라.
- 폐허 벽, 마른 나무, 바위, 깃발, 모닥불 및 바닥 그림자.
- 발의 월드 Y 좌표에 따른 앞뒤 가림과 장애물 충돌.
- 구역별 결정적 배치, 주변 구역 유지 및 먼 구역 해제. 같은 좌표를
  재방문하면 같은 배치가 재생성된다. 파일 저장을 구현한 것은 아니다.
- 창 크기에 맞춘 화면 변환, 일시정지 및 비활성 창 입력 해제.
- HDR 장면 렌더링 후 톤 매핑, 블룸, 비넷, 가장자리 블러를 합성한다.
  UI는 합성 후 표시한다. 자세한 구조와 조작은 `POST_PROCESSING.md` 참고.

이 시점, 장면 구성, 생성 규칙, 외형은 렌더링 검토용 임시 구현이다.
게임 제목 화면의 `THE LONG WAR`도 임시 문구이며 확정 게임명이 아니다.
세계관의 새로운 확정 설정이나 기본 직업별 전투 능력을 추가하지 않았다.
월드는 삼각형 기반 도형을 사용하고 플레이어는 PNG 텍스처를 사용한다.
마법사는 지팡이 없이 양손 장갑의 마법진을 표시한다.

## 사용자 빌드 및 실행 확인

기존 `SimpleGame.sln`을 Visual Studio에서 열고 사용자가 직접 빌드한다.
현재 프로젝트의 Win32/x64 라이브러리 구성은 유지했다. 실행 파일 폴더에
선택한 아키텍처와 일치하는 freeglut.dll 및 glew32.dll이 필요하다.
OpenGL 3.3 호환 프로필을 지원하는 환경이 필요하다.
PNG 로딩에는 Windows 내장 WIC를 사용하며 추가 이미지 DLL은 필요하지 않다.
사용자가 빌드하면 v2 PNG 두 장이 실행 파일 옆 `Assets/Characters`에,
이동 시트 두 장이 그 아래 `Walk` 폴더에 복사된다.
실행 파일을 다른 폴더로 옮길 때 이 폴더도 함께 옮겨야 한다.

1. 시작 화면에서 1/2을 눌러 기본 직업을 선택한다.
2. WASD 또는 방향키로 이동하고 Shift를 누른 상태에서 달린다.
3. 벽과 나무의 앞뒤를 이동하여 가림 순서와 충돌을 확인한다.
4. 시작 지점에서 계속 이동한 뒤 되돌아와 지형과 객체 배치를 확인한다.
5. 창 크기를 바꾸고 카메라와 주변 구역 표시를 확인한다.
6. P로 일시정지, R로 시작 위치 복귀, Esc 또는 창 닫기로 종료한다.
7. 다른 기본 직업의 외형은 프로그램을 다시 시작해 선택한다.
8. 캐릭터 주위에 시안의 회색 배경이 남지 않는지, 옷에 투명한 구멍이
   없는지, 양손 마법진과 검·방패가 표시되는지 확인한다.
9. 네 방향에서 올바른 걷기 줄이 재생되고, 멈춤·벽 충돌 시 걷기가 멈추는지 확인한다.
   달리면 프레임이 빨라지는지, 벽 뒤 가림과 발 아래 그림자가 유지되는지 확인한다.
10. F1 전체 후처리, F2 블룸, F3 비넷, F4 가장자리 블러를 비교한다.
    [ / ]로 노출을 조절한다. 실제 강도와 성능은 사용자 실행 확인이 필요하다.

권장 확인 창 크기는 기본값인 1280×720이다. 작은 창에서는 고정 크기의
선택 패널과 HUD가 겹칠 수 있다. UI는 GLUT 기본 영문 폰트를 사용한다.

## 코드 구성

- SimpleGame.cpp: 창, 입력, 타이머, 초기화와 종료.
- PrototypeWorld.h/.cpp: 캐릭터 선택, 이동, 카메라, 구역 배치, 충돌,
  월드 도형 및 UI 구성.
- Renderer.h/.cpp: 화면 좌표 도형을 삼각형으로 모아 GPU에 제출.
  PNG 스프라이트를 텍스처로 표시하고 최근접 필터링과 정수 배율을 사용한다.
  텍스트는 GLUT bitmap을 사용하므로 호환 프로필을 요청한다.
- SpriteImage.h/.cpp: Windows WIC로 승인된 v2 PNG를 읽고 공통 영역을
  32×52 텍셀로 샘플링한다. 시안의 회색 배경과 이어진 픽셀을 투명하게
  처리한 메모리 텍스처를 만든다. 원본 이미지 파일은 수정하지 않는다.
  이동 시트는 셀별 체크무늬 배경을 제거하고 같은 배율·발 기준점으로 정리해
  128×208 아틀라스(32×52 셀 16개)로 로딩한다.
- PostProcessing.h/.cpp, PostProcessingShaders.h: HDR 버퍼, 반 해상도 블러와
  밝은 부분 번짐, 톤 매핑·비넷·가장자리 블러 합성 및 효과 설정.
- 기존 Shaders/SolidRect.vs/.fs는 이전 실습 자료로 남겼으며 현재
  프로토타입에서는 사용하지 않는다. 새 렌더러의 셰이더는 코드에 포함하여
  실행 작업 폴더에 따른 셰이더 파일 누락을 피했다.

## 아직 구현하지 않은 내용

전투, 용사, 네임드, 군단, 의뢰, NPC 대화, 성장, 사운드, 파일 저장,
정교한 지형 생성과 대규모 좌표 정밀도 대응은 포함하지 않는다.
필드 캐릭터는 32×52 텍스처를 1배 크기로 표시하고, 직업 선택 화면에서는
2배 미리보기를 유지한다. 필드는 아래·왼쪽·오른쪽·위 방향 시트 행을 직접 사용하고
좌우 반전을 적용하지 않는다. 이전의 이미지 전체 상하 흔들림도 제거했다.
걷기는 80 월드 단위 이동마다 4프레임을 반복한다. 대각선은 실제 이동량이 큰 축을
우선한다. 시트 내 프레임마다 별도 확대하지 않고 한 배율로 맞춰 크기 변화를 줄인다.
공격·전용 달리기 프레임과 분리된 장비 레이어는 후속 작업이다.
배경 추출 규칙은 현재 시안과 이동 시트 전용이며, 다른 이미지로 교체할 때는
투명 배경 정식 에셋 로딩 또는 추출 규칙 변경이 필요하다.
구역 생성은 동기식이고 캐릭터 좌표는 float이므로 현재 버전을 완성된
무한 월드 시스템으로 간주하지 않는다. 장거리 탐험과 큰 창의 성능은
사용자 실행 확인이 필요하다.

## 검토 범위

사용자 지침에 따라 에이전트는 빌드하거나 게임을 실행하지 않는다.
프로젝트 파일 연결, 헤더 선언과 호출, 소스 및 변경 사항을 정적으로
검토한다. 실제 렌더링 결과, 컴파일·링크 성공과 성능은 미검증이다.
