# 세계·플레이어·성장

## 장르와 월드

- RPG이며 2.5D 형태로 표현한다.
- 오픈월드 게임이다.
- 월드는 미리 정해진 고정 크기에 머무르지 않고 지속적으로 커지기를 원한다.
- 지면과 시선 사이 각도가 약 60도인 내려다보기 구도를 사용한다. 지면과 오브젝트 윗면·그림자를 해당 시점에 맞추고, 캐릭터와 나무는 화면에서 세워진 모습으로 표현한다. 발·밑동의 깊이를 기준으로 가림 순서를 유지한다. 월드 확장 구현 방식은 아직 확정되지 않았다.
- 렌더링 결과를 기반으로 후처리(PostProcessing)를 적용해 분위기를 연출한다. HDR 활용, 비넷, 화면 가장자리로 갈수록 흐려지는 효과가 필요하다. 세부 강도와 수치는 조정 대상으로 둔다.
- 등불·모닥불 같은 자체 발광 오브젝트의 빛 번짐은 후처리 Bloom effect로 표현한다.

## 일반 맵과 네임드 던전의 진행 방향

- 2026-09-28 사용자 확정: 게임 흐름을 전반적으로 재구축하고, 맵을 전환하는 이동 형식에서 오픈월드 형식으로 바꾼다. 기존의 여러 작은 맵 전환 규칙보다 이 요청이 우선한다. 지역의 단서·전투·결과는 연결된 세계에서 이어진다. [현재 구현과 가정](../implementation/OPEN_WORLD_FLOW.md)을 참고한다.
- 일반 맵에서는 일반 몬스터를 사냥한다.
- 네임드를 잡는 과정은 던전 형식의 전투·조사 구성을 사용한다. 이전의 작은 맵 전환 방식은 위 오픈월드 요청으로 대체한다.
- 기존 오픈월드 방향은 유지하며 일반 맵과 네임드 던전의 역할을 나눈다.
- 아래의 구체적인 지역 배치, 첫 네임드 후보, 단서 이야기 및 구현 순서는 논의한 제안으로 보존한다. 이번 기록 요청만으로 세부 제안까지 확정한 것으로 취급하지 않는다.
- 던전별 맵 수, 입장 조건, 중간 저장, 사망 후 재시작 위치, 재도전·재입장, 적 재생성 및 보상 규칙은 미정이다.

## 시대와 세계의 상황

- 중세 암흑시대를 배경으로 한다.
- 검과 마법이 존재하는 판타지 세계이다.
- 수많은 사람이 절망 속에 살아간다.
- 절망의 원인은 수백 년간 이어진 전쟁이다.
- 전쟁이 수백 년간 지속된 이유는 첫 전투인 아크 드래곤과의 싸움에서 양측 모두 치명적인 피해를 입었기 때문이다.
- 몬스터들의 지속적인 공격으로 나라가 휘청거리고 있다.

## 일곱 영웅과 용사의 계승

- 최초의 아크 드래곤과의 싸움에서 활약한 일곱 사람을 ‘일곱 영웅’이라고 부른다.
- 일곱 영웅 중 구심점이 되었던 인물이 최초의 ‘용사’이다.
- 현재의 용사는 최초의 용사의 후예이다.
- 나머지 여섯 영웅의 정체와 각 영웅의 구체적인 행적·운명은 미정이다.
- ‘후예’의 구체적인 계승 방식은 아직 정해지지 않았다.

## 플레이어와 기본 직업, 스킬 성장

- 주인공은 용병이다.
- 플레이어는 캐릭터를 처음 생성할 때 기본 직업을 선택한다. 기존에 ‘특성’이라 부른 선택을 기본 직업으로 정리한다.
- 현재 기본 직업은 마법사와 기사이다. 권투사(권투가)는 기본 직업에서 제외한다.
- ‘전사’와 ‘기사’는 같은 직업을 가리킨다.
- 이후 다양한 스킬을 배워 플레이 스타일을 다채롭게 발전시키는 방향이다.
- 플레이어는 레벨이 오를 때마다 새로운 스킬을 획득할 수 있다.
- 레벨업 시 스킬의 자동 지급 여부, 선택 방식, 획득 가능한 스킬의 수와 목록은 미정이다.
- 마법사는 무기를 사용하지 않는다. 마법진이 그려진 장갑을 매개로 마법을 사용한다.
- 마법사는 근접공격과 원거리 공격이 모두 가능한 직업이다. 기본 공격 동작과 연계 입력은 아래 공격 항목을 따른다. 원거리 공격의 구체적인 동작·연계는 미정이다.
- 플레이어는 큼직한 도트가 드러나는 픽셀아트 스타일을 사용한다. 기사·마법사 외형은 기존 저해상도 스타일 시안을 채택하며, 이후 제안된 젊은 외형 시안은 사용하지 않는다.
- 앞으로 제작하는 모든 스프라이트(캐릭터·몬스터·오브젝트·효과 포함)는 투명 배경으로 만든다. 실제 알파 채널의 투명도를 확인하며, 체크무늬나 단색 배경을 투명 배경의 대체물로 사용하지 않는다.
- 직업은 추후 추가할 수 있으나 현재 범위는 두 기본 직업이다.
- 직업별 초기 능력, 장비 제한, 직업 간 스킬 공유 범위, 스킬 습득의 추가 조건·비용 여부, 퀵슬롯 등록 외 스킬 장착·조합의 세부 규칙, 직업 변경 여부는 미정이다.

## 플레이어 경험치와 레벨 성장

- 플레이어는 몬스터 처치, 던전 클리어, 의뢰를 통해 경험치를 얻는다.
- 획득한 경험치를 통해 플레이어의 레벨을 올릴 수 있다.
- 각 경로의 경험치 지급량·지급 시점, 레벨별 필요 경험치, 최대 레벨은 미정이다.

## 플레이어 스탯과 레벨업에 따른 능력치 성장

- 플레이어의 스탯은 HP, MP, 공격력, STR, INT이다.
- 레벨업하면 HP와 MP가 자동으로 일정량 상승한다.
- 레벨업하면 직업에 맞는 스탯이 상승하며, 해당 스탯에 따라 공격력이 상승한다.
- 직업별로 상승하는 스탯의 구체적인 대응 관계, 각 능력치의 초기값·상승량, 스탯에 따른 공격력 계산식은 미정이다.
- 레벨업 시 현재 HP·MP의 회복 여부와 스킬 획득 외 추가 보상은 미정이다.

## 상태창과 장비

- 플레이어는 상태창을 열어 자신의 상태를 확인할 수 있다.
- 상태창에는 최대 HP와 현재 HP, 최대 MP와 현재 MP, 공격력, STR, INT 수치를 표시한다.
- 상태창에서 플레이어가 현재 착용하고 있는 장비를 확인할 수 있다.
- 플레이어는 상태창에서 착용 장비를 교체할 수 있다.
- 상태창을 여는 키, 장비 슬롯의 종류와 수, 장비 교체 조작 방식과 장비의 능력치 효과는 미정이다.

## 인벤토리와 몬스터 전리품

- 플레이어에게는 인벤토리 창이 존재한다.
- 인벤토리는 캐릭터가 보유한 장비와 돈을 시각적으로 확인할 수 있어야 한다.
- 몬스터가 죽으면 돈과 아이템을 드랍한다.
- 플레이어가 획득한 돈과 아이템은 인벤토리에 저장한다.
- 인벤토리를 여는 키, 인벤토리의 용량과 정렬 방식, 전리품의 자동·수동 획득 여부, 몬스터별 드랍 목록과 확률은 미정이다.

### 이번 구현의 표시 방식 가정 — 사용자 확정 규칙과 구분

- 현재 구현은 기존 인벤토리 데이터에 맞춰 한 화면에 장비 8개를 4×2 슬롯으로 보여 주고, Page Up / Down으로 페이지를 이동한다. 실제 인벤토리 용량과 정렬 규칙을 확정한 것은 아니다.
- 4×2 슬롯을 읽을 수 없는 작은 창에서는 창을 키우라는 안내만 표시한다. 창 최소 크기 규칙을 추가한 것은 아니다.
- 지도 화면을 열면 인벤토리 창을 닫아 두 화면이 겹치지 않게 한다. 인벤토리와 지도의 동시 표시 규칙을 확정한 것은 아니다.
- 기존 장비 데이터는 각 보관 장비를 독립 항목으로 저장하므로 슬롯의 `x1` 표시는 각 항목이 한 개임을 보여 줄 뿐, 중첩 보관 규칙을 추가하지 않는다.
- 장비 아이콘은 현재 보관 가능한 철검과 룬 장갑을 구분하기 위한 화면 도형이다. 새 아이템이나 장비 효과를 추가하지 않는다.

## 마을 상점과 거래

- 플레이어는 몬스터가 드랍한 아이템을 마을에서 판매할 수 있다.
- 플레이어는 보유한 돈으로 포션과 장비를 구매할 수 있다.
- 판매·구매 가격, 상점의 종류와 위치, 판매 가능한 아이템의 범위, 포션과 장비의 구체적인 상품 목록은 미정이다.

## 스킬 피해량과 스탯 계수

- 각 스킬은 공격력 반영 비율(%)에 따라 피해를 준다.
- 기사(전사) 스킬에는 STR에 비례하는 추가 계수가 존재한다.
- 마법사 스킬에는 INT에 비례하는 추가 계수가 존재한다.
- 기본 피해 구조는 `공격력 × (스킬의 공격력 반영% / 100) + 해당 스탯 × 스킬의 추가 계수`이다.
- 스킬별 공격력 반영 비율과 추가 계수의 수치는 미정이다.

## 액티브 스킬과 패시브 스킬

- 스킬은 액티브 스킬과 패시브 스킬로 구분한다.
- 액티브 스킬은 플레이어가 직접 사용해야 효과가 발생한다.
- 패시브 스킬은 직접 사용할 수 없으며, 보유하고 있는 동안 효과가 항상 적용된다.
- 패시브 효과의 중첩 여부와 적용 조건은 미정이다.

## 액티브 스킬의 쿨타임과 MP 소모

- 플레이어와 몬스터의 액티브 스킬에는 쿨타임이 존재한다.
- 플레이어가 액티브 스킬을 사용하면 MP를 소모한다.
- 기사와 마법사의 스킬은 MP 소모량이 서로 다르다.
- 플레이어가 보유한 MP가 스킬의 필요 MP보다 적으면 해당 스킬을 사용할 수 없다.
- 스킬별 쿨타임, 기사·마법사 스킬의 구체적인 MP 소모량, MP 부족을 알리는 화면·효과음 표현은 미정이다.

## 스킬창과 퀵슬롯

- 플레이어는 스킬창에서 스킬을 확인할 수 있다.
- 화면 하단에 퀵슬롯 창을 배치한다.
- 퀵슬롯에 공격을 등록하면 해당 퀵슬롯에 대응하는 키로 등록된 스킬을 사용할 수 있다.
- 스킬창은 `K`로 열고 닫는다. 화면 하단에는 `A`, `S`, `D`, `F`, `Q`, `W`, `E`, `R` 순서의 8개 퀵슬롯을 둔다. 상호작용은 `Space`, 마을 귀환은 `B`를 사용한다.
- 스킬창의 사용 가능한 액티브 아이콘을 드래그하여 퀵슬롯에 놓으면 등록하며, 기존 등록은 교체한다. 패시브와 요구 레벨 미달 스킬은 등록하지 않는다.
- 실제 스킬명·개수·MP·쿨타임·피해 수치, 중복 등록 허용 여부의 기획 결정은 미정이다.

### 이번 구현의 입력 충돌 처리 가정 — 확정 설정과 구분

- 등록된 WASD 스킬은 이동보다 우선하고, 빈 WASD 슬롯은 기존 이동을 유지한다. 방향키 이동은 항상 유지한다.
- E/R는 스킬 전용이다. 빈 E/R 슬롯은 아무 동작도 하지 않으며, 상호작용과 귀환은 각각 `Space`, `B`를 사용한다. MP 부족·쿨타임 실패도 해당 입력을 소비한다.
- 스킬 창은 조작을 막되 게임을 자동 일시정지하지 않는다. 이 충돌 처리 방식은 구현 가정이며 향후 사용자 결정으로 변경할 수 있다.


## 챕터 3 도시·건물·출입 — 사용자 확정 (2026-10-20)

- 오픈월드를 유지하되 도시와 거리 구역이 분명히 구분되도록 만든다. 챕터 3 스토리 문서를 분석한 뒤 거리·기록관 등 필요한 공간을 순서대로 제작한다.
- 건물은 배경에 합친 그림만으로 처리하지 않고 별도 객체로 제작·배치하며 각 건물의 충돌을 처리한다. Blender로 배경을 제작하는 방식도 허용된다.
- 들어갈 수 있는 건물은 기록관뿐이며 포탈을 이용해 출입한다. 나머지 건물은 외관과 외부 조사·접견 지점으로 구성한다.
- 구획·좌표·기록관 실내 구분과 폐쇄 수도원 조사 동선의 구현 차이는 [도시 구조와 기록관 포탈](../implementation/CHAPTER_03_CITY.md)에 기록한다.
