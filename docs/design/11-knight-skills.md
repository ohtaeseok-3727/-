# 기사 스킬

## 천단참 Blender 리메이크 — 사용자 요청 (2026-10-26)

- 최신 교정: 화면이 거울로 변하는 과정과 완성 거울판 정지를 제거하고, 참격 직후 곧바로 분리 파편이 터져 나가게 한다. 파편의 형태·회전은 유지한다. 제작 시안은 24프레임까지 베기·잔상, 25프레임부터 이미 벌어진 파편으로 전환하며 게임에는 아직 적용하지 않았다.
- 후속 교정 요청: 검 휘두름 궤적과 화면 자상이 일치해야 하며, 화면은 거울처럼 깨지면서 폭발한다. 과거의 ‘분리 파편 없음’ 조건은 이번 거울 파쇄 연출에서 대체한다. [거울 파쇄 v2 제작물](../../SimpleGame/Assets/Effects/CheondanMirror-v2/README.md)은 공통 칼끝 곡선과 분리·회전·확대하는 거울 조각으로 제작하며 아직 게임 미적용이다.
- 인터넷에서 화면이 깨지는 듯한 스킬 스타일과 검을 휘두른 뒤 남는 참격 이펙트를 조사하여 Blender로 새로 제작한다. 이번 이펙트 제작에서는 아래 과거의 ‘스프라이트 없이 코드로만 제작’ 조건을 대체한다.
- 피해·MP·쿨타임·범위 변경 요청은 없으며 기존 값을 유지한다. 캐릭터 몸체·공격 동작의 재제작 요청으로 해석하지 않는다.
- [제작물과 출처·검토 범위](../../SimpleGame/Assets/Effects/CheondanBlender-v1/README.md): Blender 원본·46프레임 투명 도트 시트·재생 미리보기. 금빛 원호 참격·지연 잔상·연결된 사선 균열은 제작 선택이다. 현재 게임 적용은 하지 않았다.

## 천단참 — 사용자 확정 (2026-10-12)

- 기사 궁극기: 천단참. 습득 Lv.20, MP 30, 쿨타임 60초, 피해는 공격력 500% + STR × 5.0이다.
- 범위는 기존 검기 발산보다 위쪽 높이 5배, 이동 거리 2배다.
- 검기가 검에 모이며 검날이 점점 커진다. 거대해진 검기를 화면을 향해 사선으로 내리긋고, 그 뒤 잔상이 생긴다. 잔상을 따라 화면이 깨지는 연출로 변경한다. 이전의 지면을 향한 내려베기와 전방 폭발 연출을 대체한다. (2026-10-13 최신 요청 반영)
- 새 이펙트는 스프라이트로 제작하지 않고 코드로 직접 그린다. 연결된 거친 윤곽을 사용하고 분리된 파편을 추가하지 않는다. 기존 기사 캐릭터의 동작 시트는 유지한다.
- 피해 수치와 범위는 유지한다. 화면 균열은 연출이고 기존 지연 관통 판정은 유지하는 구현 선택을 적용했다. 구현 시간·좌표와 검기 상인 배율의 해석은 [천단참 구현](../implementation/CHEONDAN_ULTIMATE.md)에 구분해 기록한다.

## 게임 연결과 수치 — 사용자 확정 (2026-10-08)

아래 최신 확정값이 과거 문단의 미정 수치보다 우선한다. 사용자는 기사 스킬의 게임 연결을 요청했다.

| 스킬 | 습득 | MP | 쿨타임 | 피해·효과 |
| --- | --- | --- | --- | --- |
| 연속 찌르기 | Lv.3 | 4 | 5초 | 1회마다 공격력 70% + STR × 0.5, 총 6회. 사거리는 이펙트 충돌 범위 |
| 검기 상인 | Lv.5 | 없음 | 없음 | 공격력 +20%, 기본 공격·스킬 범위 +30% |
| 검기 발산 | Lv.5 | 10 | 10초 | 공격력 150% + STR × 1.0, 적 관통, 검기 상인 필수 |

검기 발산 이동 거리는 기존 미리보기와 동일하게 한다. 찌르기 1회 동작·6개 시간차 이펙트와 검기 속도 2배의 기존 확정 사항도 유지한다.

스킬창·퀵슬롯·피해·패시브·모션 연결과 수치 해석은 [기사 스킬 런타임 구현](../implementation/KNIGHT_SKILLS.md)에 기록한다. 판정 사각형·좌표 변환·반올림 등 구현 선택은 별도 게임 기획 확정으로 간주하지 않는다.

## 기사 스킬 추가 — 사용자 확정 (2026-09-22)

### 스프라이트 선택 — 사용자 확정 (2026-09-23)

- 직접 픽셀로 그린 v2는 기준 캐릭터와 모습이 달라 사용하지 않으며, 제작물과 전용 제작 도구를 제거한다.
- 이전 이미지 생성 방식의 기사 스킬 시안(`output/knight-skills-v1/`)으로 돌아간다. 이번 선택은 게임 런타임 연결을 완료했다는 뜻은 아니다.
- 원본 픽셀을 복사하지 않는 원칙과 미니 이동 시트의 고정 기준은 유지한다.

기사 전용 스킬로 아래 세 가지를 추가한다. 정식 스킬명은 현재 설명용 명칭을 사용하며, 습득 레벨·MP 소모량·쿨타임·피해 계수·상태 지속 시간은 공통 스킬 규칙을 따르되 수치는 미정으로 둔다.

### 연속 찌르기 — 액티브 스킬

- 캐릭터의 찌르기 동작은 한 번만 수행하고, 전방 찌르기 이펙트 6개는 각각 약간의 시간차를 두고 발동한다. 캐릭터 동작을 여섯 번 반복하지 않는다. 이전 동시 발동 설정을 대체한다. (2026-09-23 최신 사용자 확정)
- 6회의 이펙트는 하나의 찌르기 효과 스프라이트를 재사용한다. 6개의 서로 다른 효과 스프라이트를 제작하는 방식은 사용하지 않는다.
- 6개 이펙트의 각도는 동일하게 유지하고, 생성 위치는 앞뒤·위아래로 불규칙하게 다르게 배치한다. 정확한 시간차는 미정이며 현재 미리보기는 30ms 간격을 사용한다.
- 위치 차이는 이펙트별 가로·세로 오프셋으로 관리한다. 구체적인 오프셋과 매 사용 시 재추첨 여부는 미정이다.
- 이펙트 발동 순서는 위에서 아래로 정렬하지 않고, 위아래 위치가 불규칙하게 뒤섞이도록 한다. (2026-09-23 사용자 확정)
- 찌르기 스프라이트는 기사 미니 이동 스프라이트의 체형·픽셀 크기·색상 팔레트를 시각적 기준으로 새로 제작한다. 공격 스프라이트의 원본 픽셀을 이동 스프라이트에서 복사·재사용하지 않는다.
- 스프라이트 배경은 실제 알파 채널을 가진 투명 배경으로 제작한다.
- 각 회차의 피해 판정은 재사용 가능한 공격 인스턴스 또는 데이터 기반 이벤트로 처리하여 동일 리소스의 캐싱·재사용을 우선한다.
- 6회 각각의 공격력 반영 비율, STR 추가 계수, 공격 범위, 전방 거리, 경직·관통 여부는 미정이다.

### 검기 상인 — 패시브 스킬

- 기사의 검에 검기 효과를 항상 부여한다.
- 검기 효과가 적용되는 동안 기사의 공격력이 증가한다.
- 기본 공격 사거리가 증가한다.
- 액티브 스킬의 사거리가 증가한다.
- 검기 계열 기술을 사용할 수 있는 조건을 부여한다. 검기 계열 기술의 해금 방식과 패시브 보유 여부의 관계는 현재 명세를 따른다.
- 공격력 증가량, 기본 공격 사거리 증가량, 액티브 스킬 사거리 증가량, 검기 효과의 시각 표현과 적용 범위는 미정이다.
- 패시브는 직접 퀵슬롯에 등록하거나 입력으로 사용하는 대상이 아니다. 보유 중인 동안 효과를 적용한다.

### 검기 발산 — 검기 계열 액티브 스킬

- 기사가 검을 횡으로 휘두르는 동작을 수행한다.
- 횡베기 동작 이후 전방으로 거대한 검기를 발사한다.
- 발사체는 기사 공격 기준에 맞춘 검기 전용 스프라이트 또는 이펙트 리소스로 제작하며, 실제 알파 채널 투명 배경을 사용한다.
- 검기는 생성 후 전방으로 이동하는 별도 공격 객체로 처리한다. 플레이어의 근접 검과 검기 발사체의 생명주기·판정을 분리한다.
- 검기 발사체의 이동 속도는 기존 미리보기 대비 2배로 한다. (2026-09-23 사용자 요청) 미리보기는 이동 거리를 유지하며 비행·소멸 시간을 840ms에서 420ms로 줄인다. 캐릭터 모션 속도는 유지한다.
- 검기의 크기, 이동 속도, 이동 거리, 공격력 반영 비율, STR 추가 계수, 관통 여부, 충돌 횟수, 경직·넉백 여부는 미정이다.
- 검기 상인 패시브를 보유한 기사만 검기 발산을 사용할 수 있는지 여부와 별도 습득 조건은 미정이다.

### 기사 스킬 공통 구현 기준

- 세 스킬은 기사 전용 스킬 목록에 등록하고, 스킬창·퀵슬롯·액티브/패시브 규칙과 연결한다.
- 액티브 스킬은 MP 부족 시 사용하지 않으며, 사용 후 쿨타임을 적용한다. 구체적인 수치는 미정이다.
- 스킬 데이터와 실행 로직은 분리한다. 스킬별 타이밍·오프셋·각도·피해 계수는 하드코딩을 최소화하고 조정 가능한 데이터로 관리한다.
- 스프라이트·공격 객체·피해 판정은 각 책임별 클래스 또는 모듈로 분리한다.
- 현재 확정된 내용은 스킬의 동작 개념과 리소스 재사용 원칙이다. 수치 밸런스, 입력 키, 습득 레벨, 정식 명칭은 사용자 확정 전까지 임의로 결정하지 않는다.
