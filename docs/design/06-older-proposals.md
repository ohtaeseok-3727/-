# 기존 미확정 제안

## 확정 설정과 구분할 기존 제안

다음은 대화 중 에이전트가 제안한 사항으로, 사용자가 확정한 요구사항이 아니다.

- 청크·시드를 이용한 절차적 월드 생성과 주변 구역 로딩.
- 의뢰 수락 → 탐험·전투 → 보상·성장이라는 구체적인 반복 구조.
- 특성별 전투 역할 및 스킬 예시.
- 여러 네임드 중 하나를 처치하면 용사 영입 조건을 충족하는 방식.
- 네임드 토벌에 따른 군단 해체·후퇴 및 지역 재건.
- 수작업 핵심 이야기와 절차적 탐험 지역을 혼합하는 방식.

이 제안들은 추후 검토할 수 있으나, 확정된 설정으로 전제하지 않는다.

### 일반 맵과 첫 던전 발견 구성안 — 미확정 제안

- 용병 마을을 중심으로 일반 맵이 가지처럼 뻗고, 주요 길과 샛길·우회로가 연결되는 구조를 추천했다.
- 일반 맵의 구역은 장소를 나눈 개념이며, 구역마다 반드시 로딩 화면으로 분리하는 것은 아니다. 실제 로딩 방식은 미정이다.
- 초기 구역 후보와 역할:

| 구역 | 지형과 역할 |
|---|---|
| 용병 마을 | 여관·상점·출입구를 연결하는 의뢰 및 정비 거점 |
| 외곽 농경지 | 넓은 길, 밭, 돌담, 버려진 농가에서 첫 사냥과 피해 확인 |
| 강변 야영지 | 강변 길과 징검다리로 구성한 선택 탐험 구역, 행상인 습격 흔적 |
| 수레길 숲 | 굽은 큰길과 좁은 샛길에서 보급품 운반 흔적 추적 |
| 옛 전쟁터 | 공터·참호·공성병기 잔해 사이에서 군단의 조직적 활동 확인 |
| 숲속 군단 전초기지 | 여러 접근 경로가 있는 야외 진지에서 네임드와 던전의 관계 확인 |
| 폐광 입구 | 좁아지는 접근로와 넓은 입구 공간으로 첫 던전의 경계 표현 |

연결 구상:

```text
                         [버려진 감시탑]
                               |
[용병 마을] -- [외곽 농경지] -- [옛 전쟁터] -- [숲속 군단 전초기지]
                    |                |                  |
              [강변 야영지] -- [수레길 숲] -------- [폐광 입구]
                                                       |
                                                [첫 네임드 던전]
```

- 버려진 감시탑은 선택 탐험 장소 후보이며 초기 구현 필수 구역으로 정하지 않았다.
- 이후 확장 지역 후보는 침수된 폐도시, 협곡 광산, 재가 내리는 화산 지대, 버려진 성채이다.
- 필수 단서는 주요 경로에 두고 선택 경로에는 추가 이야기·보상을 둔다. 단서를 먼저 찾은 경우도 기록해 자유로운 탐험과 이야기 진행이 충돌하지 않게 하는 방식을 추천했다.
- 던전 입구의 조기 발견을 허용하고, 발견 후 마을 귀환 지름길을 여는 방식을 제안했다. 실제 입장 제한 여부는 미정이다.

### 첫 던전 발견까지의 이야기안 — 미확정 제안

1. 용병 마을에서 농경지의 일반 몬스터를 처리하는 의뢰를 받는다.
2. 농가에서 식량과 도구만 골라 사라진 흔적, 숲으로 이어지는 수레 자국을 발견한다.
3. 강변의 행상인 습격 흔적과 숲의 버려진 수레·보급품을 조사한다.
4. 옛 전쟁터에서 동일한 표식의 몬스터들을 만나 군단의 조직적인 보급 활동임을 알아낸다.
5. 전초기지에서 보급품이 폐광으로 운반되며 네임드가 이를 지휘한다는 단서를 얻는다.
6. 폐광 입구를 발견하고 마을에서 정비한 뒤 던전 토벌에 도전한다.

- 첫 네임드는 고블린 군단 지휘관, 첫 던전은 폐광을 후보로 제안했으며 확정하지 않았다.
- 던전 구성 예시는 입구 경계 구역 → 갈림길 구역 → 네임드 전투 구역이다. 선택 보급 창고, 우회로, 지름길을 추가할 수 있다.
- 첫 네임드 처치 이후 용사가 찾아오는 기존 확정 이야기와 연결하는 방식을 제안했다. 구체적인 연출과 발생 시점은 미정이다.

### 구현 순서안 — 미확정 제안, 구현 완료 기록 아님

1. 첫 지역 범위와 출입구·주요 길·샛길·막힌 지형을 정한다.
2. 맵·구역·전환·충돌·몬스터 생성·퀘스트·던전 관리 책임을 별도 파일의 모듈로 나눈다.
3. 임시 도형으로 마을과 농경지부터 연결하고 나머지 구역의 이동 경로를 만든다.
4. 장애물 충돌, 발 위치 기준 가림 순서, 카메라를 연결한다.
5. 농경지에서 몬스터 생성·이동·발견·추적·공격·처치 흐름을 만든 뒤 구역별로 확장한다.
6. 사냥 의뢰부터 던전 발견까지 진행 상태와 사건 기록을 관리한다. 단서의 선행 발견도 처리한다.
7. 단서 조사 대상과 상호작용을 맵에 배치한다.
8. 폐광 진입 및 귀환 위치 보존, 귀환 지름길을 연결한다.
9. 작은 맵들을 이동하는 던전과 네임드 전투를 구현한다.
10. 의뢰부터 첫 네임드 처치까지 연결한 뒤 지형 장식·스프라이트·조명·효과음을 추가한다.

- 모듈 이름 예시: `WorldMap`, `MapRegion`, `MapTransition`, `CollisionSystem`, `SpawnSystem`, `QuestSystem`, `DungeonInstance`, `Interactable`. 실제 클래스 구조는 기존 코드 검토 후 정한다.
- 데이터만 다른 구역은 공통 클래스와 별도 배치 데이터로 관리하는 방식을 추천했다.
- 첫 작업 단위로 마을과 농경지의 연결 및 장애물 충돌 이동을 추천했다.
- 코드 작성은 위 사용자 확정 개발 원칙을 따른다. 빌드·실행 확인은 사용자가 직접 수행하며 명시적 요청 없이 에이전트가 수행하지 않는다.

## 2026-11-05 현재 구현 보완 우선순위 검토 — 미확정 제안

사용자의 보완·추가 항목 질문에 대한 정적 검토 결과다. 아래 순서와 기능 범위는 에이전트 제안이며 사용자 승인이나 구현 착수 결정이 아니다. 과거의 미구현 설명보다 현재 소스와 최신 후속 기록을 우선했다.

### 확인한 사실과 출처

- 게임 종료 후 저장/불러오기는 지원하지 않는다고 [여정 화면](../../SimpleGame/src/ui/ExpeditionView.cpp)과 [종료 메뉴](../../SimpleGame/src/ui/SettingsMenu.cpp)에 명시되어 있다. 야영지의 세션 내 복귀 지점과 영구 저장은 구분한다.
- [일반 챕터 등록](../../SimpleGame/src/chapters/ChapterCatalog.cpp)은 C01~C03이다. C04는 아직 등록하지 않았다. [챕터 3 구현](../implementation/CHAPTER_03_IMPLEMENTATION.md)의 최신 인물 적용 기록은 대기 자세를 재사용하며 이동 애니메이션을 추가하지 않았다고 명시한다.
- [목표 안내와 전투 판독성](../implementation/COMBAT_GUIDANCE_POLISH.md)에 공격 예고와 상호작용 안내가 이미 구현되어 있다. [SkillSystem](../../SimpleGame/src/player/SkillSystem.cpp)에도 마나 부족·재사용 대기 알림이 있다. 이를 신규 누락 기능으로 판단하지 않는다.
- [인벤토리](../../SimpleGame/src/player/PlayerInventory.h)는 금화와 공격력 장비 중심이다. 현재 소스 검색에서 포션 구매·전리품 판매의 거래 경로와 오디오 재생 연결을 찾지 못했다. 이는 검색 범위의 정적 판단이며 실행 확인 결과는 아니다. 거래 자체는 [세계·플레이어 기획](02-world-and-player.md)에 있으나 가격과 상품 구성은 미정이다.
- [시스템 메뉴와 UI](../implementation/SYSTEM_MENU.md)는 2026-11-03 개편 기록이 있다. [성능 이력](../performance/PERFORMANCE_ANALYSIS.md)의 같은 날짜 프레임 대기 수정은 수정 후 실행 성능이 미확인이다. 예전 자동 플레이 결과를 현재 GLFW·UI 버전의 검증으로 간주하지 않는다.

### 제안 순서와 완료 판단 기준

1. **현재 C01~C03 진행 확인:** 두 직업의 주요 진행, 보스 재도전, 지역 재방문, 포탈, 메뉴와 포커스 복귀를 확인한다. 프레임 저하 수정도 같은 조건의 로그로 확인한다. 이번 검토에서는 빌드·게임·검증 프로그램을 실행하지 않았다.
2. **저장·이어하기:** 직업, 성장, 장비·금화, 퀵슬롯, 챕터 선택·증거·진행과 복귀 위치를 보존한다. 종료 후 같은 진행을 이어가고 보상이 중복되지 않는 것이 완료 기준이다. 저장 시점·슬롯·전투 중 복원 정책은 구현 전에 정한다.
3. **전투 피드백:** 기본 공격·피격·스킬 효과음, 명중과 방어/패링 반응, 큰 스킬 중 적의 공격 예고 가독성을 보완한다. 기존 경고와 실패 알림을 재사용하며 과도한 효과 여부는 실제 플레이로 판단한다.
4. **성장·거래의 연결:** 전리품 판매 → 포션/장비 구매 → 재출격을 우선 연결한다. 장비 비교·선택 착용과 소모품 사용은 후속 후보이며 확정 규칙이 아니다. 가격·상품·포션 효과는 임의 확정하지 않는다.
5. **시각 자산 마감:** 플레이어 대기/이동/공격 연결, C03 이동 인물의 모션, 조사 장치와 임시 도형을 우선 대조한다. 부족한 항목만 보완하며 기존 승인 스타일과 적용 범위를 유지한다.
6. **C04 이후 확장:** 앞 항목의 진행 보존과 기본 플레이 확인 뒤 후속 챕터로 확장하는 순서를 권한다. 구체적인 다음 챕터 범위는 별도 작업에서 최종 스토리·제작 문서를 확인한다.
