# 게임 기획 — 사용자 확정 설정

최종 정리: 2026-09-17

이 문서는 사용자가 직접 설명한 프로젝트 설정을 보존한다. 이후 기획과 구현의 기준으로 사용하며, 에이전트가 제안한 아이디어는 사용자 확정 없이 설정에 포함하지 않는다.

## 사용자 확정 개발 원칙

- 챕터 2 전투 스프라이트의 반투명 테두리·프레임 정렬을 수정하고 각 모션 사이 여백을 넓힌다. 기존 신규 포즈를 보존하는 스크립트 알파 보정·재배치를 승인했다. 이동 시트 픽셀을 공격 동작에 복사하는 작업이 아니다. (2026-09-24)

- 챕터 2 적 스프라이트를 제작한다. 오크 군단장 바르칸의 공격은 기본 무기 휘두르기, 플레이어가 멀어지면 점프하여 플레이어 위치에 내려찍기, 주변 적을 밀쳐내고 공격속도가 증가하는 전투의 함성이다. (2026-09-24 사용자 확정)
- 위 함성의 '주변 적'의 구체적인 대상, 공격속도 증가의 적용 대상·수치·지속시간, 점프 발동 거리와 목표 위치 확정 시점은 아직 미정이다. 스프라이트 제작만으로 전투 로직 구현이 완료된 것은 아니다.

- 챕터 2 본편 구현에 필요한 밑작업을 진행한다. 기존의 과도한 클래스 분리 방지 원칙을 유지한다. (2026-09-24 사용자 요청)

- 챕터 추가가 용이하도록 기존 구조를 전반적으로 개편한다. 클래스를 과도하게 잘게 분리하지 않고, 역할과 연결을 확인하기 쉬운 구성을 유지한다. (2026-09-24 사용자 요청)

- Chapter 2 스프라이트는 `_game_resource_production`을 참고한다. 현재 제작 대상은 일반 오크, 오크 엘리트, 오크 군단장 바르칸 3종으로 한정한다. 오크와 오크 군단장은 플레이어보다 크게 제작한다. 정확한 크기 배율은 미확정이다. (2026-09-22 요청)

- 성능 개선과 구조 변경을 위한 분석 자료를 지속적으로 누적한다. 실행 성능 로그와 변경별 분석 기록을 상세히 남겨 이후 비교에 활용한다. (2026-09-22 확정)
- 동일 오브젝트의 캐싱·인스턴스 재사용을 활용하고 렌더링 비용을 최적화한다. 구체적인 구현 방식과 성능 목표 수치는 측정 결과에 따라 결정한다. (2026-09-22 요청)
- Chapter 1은 `_story_scene_production/05_final_chapters/CHAPTER_01_FINAL.md`와 최신 `_game_resource_production` C01 문서를 기준으로 실제 구현한다. 이 범위에서는 확정 스토리 → 최신 C01 설계 → 본 문서 → 기존 코드 순으로 적용한다. 기존 튜토리얼의 상충하는 흐름을 대체하며, 세 기본 맵·그르마 군단 지휘전·플레이어의 전략 성공 뒤 용사 등장·장부를 통한 Chapter 2 연결을 구현한다. 이번 문서 실행 요청은 빌드·검증을 포함한다. (2026-09-21)
- Actor–SceneGraph–Renderer 구조로 렌더링을 최적화한다. (2026-09-21 확정)
- 코딩 작업은 기본적으로 아스트라가 직접 수행한다. 여러 독립적인 작업을 동시에 수행하는 경우에만 서브 에이전트를 사용한다. 기존 Terra 우선 위임 규칙보다 이 지시를 우선한다. (2026-09-21 확정)
- 코드 컨벤션은 줄바꿈을 넉넉히 사용하는 방식으로 통일한다.
- 앞으로 코드를 작성할 때 객체지향 프로그래밍으로 진행한다.
- 서로 다른 기능을 생성할 때마다 기능별 클래스·모듈을 별도 파일로 분리하고, 모듈 간 연결을 통해 동작하도록 구성한다.
- 필요하다면 STL을 비롯한 최신 C++ 기능을 최대한 활용한다. 프로젝트의 C++ 표준 및 컴파일러 지원 범위에 맞춰 적용한다.
- 코드 작성·수정 후에는 파일·클래스의 역할, 모듈 간 연결과 실행 흐름을 설명한다. 사용한 STL 및 최신 C++ 기능이 어떤 역할을 하며 왜 선택했는지도 설명한다.
- 게임 화면과 콘솔 안내 문구는 한국어로 표시한다. 입력 키 이름은 실제 키 표기를 유지한다.
- 콘솔에 프레임당 실제 OpenGL `glDraw*` 호출 수와 FPS를 성능 기본 정보로 표시한다.

### 이번 구현의 성능 로그 방식 가정 — 사용자 확정 규칙과 구분

- 콘솔 과다 출력을 피하기 위해 최근 약 1초 구간의 프레임 수, FPS, 프레임당 평균 `glDraw` 호출 수와 최신 프레임 호출 수를 출력한다. 출력 간격은 현재 구현값이다.
