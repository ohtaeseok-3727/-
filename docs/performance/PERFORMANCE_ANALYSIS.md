# 성능 분석 및 구조 변경 이력

## 기록 원칙

- 앞으로 성능·구조 변경마다 아래 이력에 추가한다. 이전 관측 결과는 덮어쓰지 않는다.
- 사용자 제공 로그, 코드 정적 분석, 실행 실측, 원인 가설을 구분한다.
- FPS를 낮추는 것이 목표가 아니다. 동일 조건에서 프레임 지연, CPU/GPU 비용과 불필요한 전송을 줄이는 것이 목표다.
- 화면 크기, Debug/Release, GPU/드라이버, 맵·이동 경로·적 수, 열린 UI, 후처리 옵션, 포커스 상태를 맞춰 비교한다.
- 빌드·실행은 사용자가 수행한다. 실행하지 않은 결과나 개선율을 추정값으로 채우지 않는다.

## 자동 실행 로그 — schema 2

게임 실행 시 현재 작업 디렉터리를 기준으로 한 상대 경로 `runtime-logs/performance/`에 UTC 시각과 프로세스 ID로 구분한 `session-*.csv`와 `session-*.csv.txt`를 생성한다. CSV는 약 1초마다 한 줄씩 기록하고 정상 종료 시 남은 구간도 기록한다. 실행별 최대 86,400행에서 파일 기록을 중단하고 콘솔 집계는 유지한다. 과거 실행 파일은 자동 삭제하지 않으므로 장기 누적 시 사용자가 보관·정리한다. 이 폴더는 Git에서 제외된다.

파일 생성·쓰기 실패는 콘솔로 알리고 게임을 계속한다. 1초마다 파일 버퍼를 비우므로 비정상 종료 시 마지막 미집계 구간이 유실될 수 있다. 디스크 쓰기와 콘솔 출력은 동기 방식이다. 비용은 다음 프레임 간격에 포함되지만 active CPU 구간에는 포함되지 않는다. 이 비용이 유의미하면 다음 변경에서 비동기 기록을 검토한다.

메타데이터에는 계측 개정명, 소스 빌드 시각, Debug/Release 및 OpenGL vendor(7936), renderer(7937), version(7938)을 기록한다. 개정명은 Git 커밋 해시가 아니다. 비교 자료를 보관할 때 해당 브랜치·커밋과 미커밋 변경 여부를 함께 기록한다.

## 2026-09-22 — 공유 원형 캐시, 순서 보존 배치, 지속 계측

브랜치: `codex/render-performance-analysis`. 시작 시 기존 Chapter 1 및 렌더 구조 변경이 미커밋 상태였으며 이를 유지한 채 수정했다.

### 관측

사용자 제공 8개 구간: FPS 15.1~60.6, 평균 glDraw 31.0~52.0회/프레임. FPS 15.1 구간은 44프레임이므로 약 2.91초에 걸친 집계다. 이 로그만으로 GPU 과부하, 파일 로딩, 스케줄링 지연 중 원인을 확정할 수 없다. 51회 정도의 드로우 콜 자체도 병목의 증거가 아니다.

정적 분석에서 확인한 내용:

- Sprite·캐릭터·문자열 그리기가 호출 전후 Flush를 강제해 리소스를 공유해도 작은 배치가 많아졌다.
- 기존 Chapter1Sprites의 텍스처와 문자 텍스처는 이미 캐시된다. 이를 새 캐시인 것처럼 중복 구현하지 않는다.
- 나무·석조물·바위 원형을 매 프레임 다시 만들고, 타원마다 반복 삼각함수를 계산했다.
- 일부 스프라이트는 첫 표시 때 로드된다. 초기 지연의 후보지만 실측 원인으로 확정하지 않는다.

### 변경 및 연결

1. `SceneRenderer`가 정적 소품 kind 0~2를 로컬 좌표·크기 1의 원형으로 처음 한 번 생성한다.
2. `GeometryCache`가 종류별 불변 정점을 보관한다. `Renderer`가 원형에 위치·크기만 적용해 기존 정점 배치에 넣는다. 바람·불꽃처럼 시간에 따라 바뀌는 오브젝트는 제외한다.
3. 타원 외곽 21개 좌표를 정적 `std::array`에 한 번 계산한다. 각 타원은 이를 크기·색상별로 재사용한다.
4. 같은 텍스처의 연속 Sprite와 사이의 단색 도형을 한 배치로 제출한다. 단색 도형은 기존 셰이더의 UV=-1 경로를 사용한다. 깊이 순서를 바꾸는 텍스처별 재정렬은 하지 않는다.
5. 가산 합성 전후와 월드/후처리/UI 경계에서는 반드시 Flush한다. Text는 Prepare 전에 Flush하여 캐시 퇴출로 대기 정점의 텍스처가 삭제되는 것을 막고, 뒤따르는 도형은 문자 배치에 합친다. 기존 문자 너비도 캐시에서 조회한다.
6. `FrameProfiler`가 구간 집계·파일 기록을 담당한다. `Renderer`, `SimpleGame`과 후처리의 기존 실제 glDraw 계측 지점이 정보를 전달한다.

`std::vector`는 프레임 간 용량을 재사용하며, `std::array`는 고정 크기 원형/단계별 카운터를 저장한다. 기존 `std::unordered_map` 문자열 캐시는 조회를 재사용한다. `std::chrono::steady_clock`은 시스템 시각 변경과 무관한 간격 측정에 사용한다. 프로젝트 MSVC 설정에 맞춰 구현했으며 새 외부 의존성은 없다.

현재 방식은 **공유 원형 + CPU에서 변환한 정점 배치**다. `glDraw*Instanced`를 사용하는 GPU 인스턴싱은 구현하지 않았다. CPU 정점 변환·복사와 업로드는 남는다. 이것이 실제 병목이면 투명 오브젝트 순서를 유지하는 인스턴스 버퍼 방식으로 확장한다.

### 검토와 남은 확인

- 정적 검토 완료: 배치의 텍스처 수명, 가산 합성 경계, 소품 원형 좌표 변환, CSV 37개 필드의 순서·단위, 프로젝트 파일 등록을 확인했다. 프로젝트·필터 XML 파싱, 변경 파일의 clang-format 검사 및 git diff --check가 통과했다.
- 빌드·게임 실행·실측 성능 비교: 미수행. 사용자 실행 후 결과를 아래 후속 기록에 추가해야 한다.
- 예상 효과는 반복 CPU 계산과 불필요한 배치 감소이며, 실제 FPS/드로우 콜 개선율은 아직 없다.
- 문자별 텍스처 전환, 최초 로드, 후처리 GPU 비용은 남는다. 모든 스프라이트·UI를 한 드로우 콜로 합친 구조는 아니다.

같은 구성으로 타이틀 대기 → 동일 맵 30초 이동 → 적 다수 전투 → 인벤토리/스킬창 → 후처리 F1/F2 비교 → 포커스 이탈·복귀를 수행한다. 각 구간 시각과 조건을 기록하고 CSV와 메타데이터를 함께 보관한다. 기존 실행 파일이 있다면 같은 경로로 비교하며, 최초 로드 구간을 정상 플레이와 별도로 비교한다.

## 2026-09-22 — 적 FSM 및 A* 추적

- 브랜치: `codex/enemy-fsm-astar`. 시작 시 기존 미커밋 변경을 유지했다.
- 관측(정적): 기존 `EnemySystem::Update`는 플레이어 방향 직진과 축별 이동만 시도하여 장애물 뒤 목표로의 우회 경로를 계획하지 못했다. 행동 분기와 치유·공격·이동이 한 메서드에 섞여 있었다. 실행 비교 로그는 없다.
- 원인 가설: 나무·벽에 막힐 때 국소적인 이동 방향 변경만으로는 우회로를 찾기 어렵다. A*는 우회 계획을 제공하지만 기존 직진보다 CPU 비용이 증가할 수 있다.
- 변경: `EnemyAIState`가 개별 상태·경로를 보유하고 `EnemyStateMachine`이 전환·전투·경로 추종을 담당한다. `EnemyPathfinder`는 맵 충돌을 확인하는 8방향 A*를 담당한다. `EnemySystem`은 생성·피격·업데이트를 연결한다.
- 비용 제한: 업데이트당 최대 2회 탐색, 탐색당 최대 4,096개 노드 확장, 최대 128×128 격자. 성공 후 0.45초·실패 후 0.8초 동안 경로를 재사용하거나 재시도를 유예한다. 먼저 갱신하는 적을 순환시켜 탐색 요청의 기아를 방지한다. 이는 실행시간 보장이 아니며 충돌 검사 비용은 남는다.
- STL/표준: `enum class`는 상태 혼동을 막고 `std::priority_queue`는 예상 총비용이 낮은 A* 노드를 우선 선택한다. `std::vector`는 경로·비용·부모 인덱스를 저장한다. MSVC v143 및 기존 표준 설정 범위에서 사용 가능한 기능이며 새 외부 의존성은 없다.
- 정적 검토: 공격 준비 종료 시 거리·시야 재검사, 피격 시 공격 취소, 사망·지원 차단, 맵 revision 변경 시 경로 폐기, 슬롯 재사용 시 AI 초기화, 탐색 실패 시 정지 및 대각 모서리 검사를 확인했다. 프로젝트/필터 XML 파싱, 신규 파일 5개의 각 1회 등록·존재 확인, 변경 C++ 파일 7개의 clang-format 검사, 변경 추적 파일의 git diff --check가 통과했다.
- 빌드·실행·실측: 사용자 지침에 따라 미수행. 개선율이나 FPS 향상을 주장하지 않는다. 실행 로그의 필드·단위·저장 위치는 변경하지 않았으며 schema 1을 유지한다.
- 한계: 격자 간격 24와 탐색 사각형 여유 384로 표현하지 못하는 좁은 통로·긴 우회로는 실패할 수 있다. 동적 적끼리의 충돌·군집 회피는 포함하지 않는다. 플레이어 이동 반영은 재탐색 주기와 요청 대기시간만큼 늦어질 수 있다. 시작점·목표가 기존 맵 충돌상 막혀 있으면 탐색하지 않는다.
- 사용자 비교 조건: 동일 빌드 구성·시드·맵·적 수·이동 경로·화면·후처리 상태에서 기존 `update_mean_ms`와 프레임 지연을 비교한다. 나무 뒤 추적, 벽·강 건너 우회, 원거리 사격 시야, 이동 목표, 감지 범위 이탈, 피격 취소, 지원 차단/복원, 보스 부상, 맵 전환을 실행 확인한다.
