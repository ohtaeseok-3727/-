# C03~C18 개발 착수 안내 — 빠른 읽기

2026-10-20 · 상태: `SPEC_READY`(개발 준비 문서). 게임 구현·자산 제작 완료를 뜻하지 않는다.

## 다음 요청을 받으면

1. `local_knowledge.py search "C04 개발 준비"`처럼 대상 장을 DB에서 검색한다. 작업 이력·함수도 로컬 DB에서 먼저 찾는다.
2. 아래 표의 해당 장 문서와 [공통 구현 지침](C03_C18_IMPLEMENTATION_GUIDE.md)을 읽는다. 자산 작업 때만 [공유 리소스 장부](../02_resource_ledger/C03_C18_SHARED_RESOURCES.md)를 추가로 읽는다.
3. [작성 당시 기준 파일](C03_C18_SOURCE_SNAPSHOT.json)의 SHA-256과 대상 원본의 현재 값을 비교한다. 달라진 파일과 문서의 해당 항목만 다시 확인한다. 최종 스토리를 고치지 않는다.
4. 선행 장 결과, 현재 소스, 미커밋 변경을 확인하고 새 독립 작업은 `codex/` 브랜치에서 시작한다. 같은 작업의 연장은 현재 브랜치를 유지한다. 로컬 작업 DB에 시작/종료를 기록한다.
5. 해당 장의 P0→P1→P2 순서로 구현한다. 제안 ID·수치·폴더는 실제 프로젝트와 충돌을 확인하고 채택한다. 빌드·실행은 별도 명시 요청이 있을 때만 한다.
6. 변경한 구현 현황·리소스 상태를 문서에 기록하고 문서 인덱스와 검색 DB를 갱신한다. 대상 장과 핵심 기믹으로 재검색한다.

빠른 기계 조회에는 [소스 스냅샷 JSON](C03_C18_SOURCE_SNAPSHOT.json)의 대상 `chapter` 항목을 사용한다. 검색 키, 원본/준비 문서, 해시, 장면 ID, 문서용 맵/리소스 ID가 있다. [검토 기록](C03_C18_READINESS_AUDIT.md)에는 16개 장 123개 장면의 대응 범위와 남은 검증을 기록했다.

## 현황과 범위

- 현재 소스의 정상 챕터 등록은 C01~C03뿐이다. C03은 4지역, 전체 10지역이다. C04~C18의 장면 로직·전용 적·완성 맵·최종 자산은 이 문서 작성으로 생기지 않는다.
- C03은 처음부터 다시 만들지 않는다. 최신 [도시·포탈 구현](../../docs/implementation/CHAPTER_03_CITY.md)과 현재 미커밋 코드를 기준으로 잔여 작업을 한다.
- 각 장 표의 장면 사실은 해당 최종본에서 추출했다. 맵 통합, 클래스 설계, 제안 플래그, 자산 묶음과 제작 우선순위는 개발 제안이다. 숫자 밸런스·프레임 수·배치 좌표는 미확정이다.
- 기존 C01/C02 매니페스트는 당시 범위의 기록이다. 이 문서 묶음이 후속 개발의 진입점이며 과거 경로/상태를 현재 검증값으로 복사하지 않는다.
- 새 PNG·Blender 원본·게임 코드·음원은 제작하지 않았다. 자산 존재 확인은 파일 목록/로더의 정적 확인이고 알파·화면·소리 품질 검증이 아니다.
